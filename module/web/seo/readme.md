# SEO与GEO

SEO与GEO是两个不同的概念，但目标都是为了提高网站排名，一个是提高搜索引擎的排名，一个是提高AI推荐的排名。从web技术的角度聊聊如何在日常开发中融入SEO优化的思路。从当前AI浪潮中聊聊GEO是什么，它与SEO有什么关系。

## 1. SEO

SEO 是 Search Engine Optimization 的缩写，意为搜索引擎优化。既然是搜索引擎优化，那么就要从搜索引擎的原理说起。搜索引擎的原理是：搜索引擎通过爬虫爬取网站内容，然后通过算法对网站内容进行排序，最后将排序结果展示给用户。

既然是用爬虫爬取网站，那么就必定有其爬取的规则，而我们在日常开发中需要熟知这些规则，才能让搜索引擎更好地爬取我们的网站。

### 1.1如何引导爬虫去抓取网站内容

- 通过 `sitemap.xml` 文件告诉爬虫哪些页面需要抓取
- 通过 `robots.txt` 文件告诉爬虫哪些页面不需要抓取
- 通过 `<a href="xxx">` 标签告诉爬虫哪些页面需要抓取

**sitemap.xml**

`sitemap.xml` 文件是搜索引擎用来抓取网站内容的文件。它是一个XML文件，其中包含网站中我们想要被抓取页面的URL列表。搜索引擎通过抓取 `sitemap.xml` 文件来了解网站的结构和内容。

`sitemap.xml` 文件生成好，待网站上线后。需要再GSC控制台中提交该文件，以告知搜索引擎该网站的结构和内容。

**robots.txt**

`robots.txt` 文件是搜索引擎用来告诉爬虫哪些页面不需要抓取的文件。它是一个文本文件，其中包含搜索引擎爬虫不能访问的页面列表。搜索引擎通过抓取 `robots.txt` 文件来了解网站的屏蔽策略。 该文件需要放在网站的根目录下，以供爬虫抓取。

**`<a href="xxx">`**

`<a href="xxx">` 标签是HTML中用来告诉搜索引擎哪些页面需要抓取的标签。搜索引擎通过抓取 `href` 属性中的URL来了解网站的结构和内容。a链接和sitemap.xml文件都是用来告诉搜索引擎哪些页面需要抓取的，一个需要SEO的网站可以没有sitemap.xml文件，但是不能没有a链接。没有sietmap.xml文件搜索引擎只是收录的页面会慢一些，或者不全。但是没有a链接，搜索引擎连页面都抓取不到，更别说收录了。

所以，一个SEO的站点，A链接是重中之重。而链接路径的写法也是有讲究的，比如：

```html
<a href="https://www.example.com/page1">页面1</a>
<a href="https://www.example.com/page2">页面2</a>
```

以上代码中，爬虫会根据不同的href去收录不同的页面。且它们之间没有层级关系，互不隶属。

```html
<a href="https://www.example.com/store">页面1</a>
<a href="https://www.example.com/store/category">页面2</a>
<a href="https://www.example.com/store/category/keychains">页面2</a>
```

以上代码中，URL路径是有层级关系的，语义明确。会影响网页的收录权重，且用户也可以通过链接知道自己所属的位置。

```html
<a href="https://www.example.com/store">页面1</a>
<a href="https://www.example.com/store?all-products=category">页面2</a>
<a
  href="https://www.example.com/store?all-products=category&category-type=keychains"
  >页面2</a
>
```

以上是存在问题的，因为搜索引擎可能会认为页面1、2、3是同一个页面。进而引发“内容重复”问题。这时候就会对页面权重降低。

根据这几个示例，我们可以总结出以下几点：

- 链接路径的写法要有语义
- 链接路径的写法要有层级关系，层层递进。
- 不同的页面不能使用链接查询参数来区分，而应该要通过路径来区分页面。
- 链接查询参数可以使用的场景为：确实是同一个页面结构，但内容需要通过分页或其他筛选方式来展示。

```html
<a href="https://www.example.com/store/category/keychains?page=1">页面1</a>
```

这种写法是正确的，而page信息也必须使用查询参数，因为当前页面确实需要分页。但分页信息不能放在路径中，最佳实践是使用查询参数的方式来告知爬虫当前页码。

#### 1.1.1 日常开发中的最佳实践

当我们了解了`sitemap.xml`、`robots.txt`、`<a href="xxx">`标签的用法后，在日常开发中则需要关注这些文件的维护与页面的跳转方式。

目前项目中，在需要做SEO优化的页面，还是存在不少使用JS的跳转方式，这种跳转搜索引擎无法识别，进而影响网站的收录。所以，在日常开发中，需要避免使用JS的跳转方式。

目前项目中，在需要做SEO优化的页面，还存在路径不规范的情况，本应该用路径来区分不同的页面，却使用了查询参数来区分。这种写法会导致搜索引擎降低页面权重或不去收录。

**总结**：SEO优化是一个长期的过程，它伴随着网站的运营而持续进行。所以，在一个需要做SEO优化的项目中，特别是明确规定需要优化的页面，应该摒弃SPA（单页应用）开发的思维模式，需要避免使用JS的跳转方式，以及路径不规范的情况。

### 1.2 网站内容对SEO算法的影响

网站内容对SEO算法的影响是多方面的，比如：

- 网站内容的质量
- 网站内容的数量
- 网站内容的更新频率
- 网站内容的结构
- 网站内容的语言

从一个技术的角度来看，网站内容的质量、数量、更新频率等这些确实超出了职责范围。我们深耕技术领域与需求迭代，较少的关注用户诉求、圈子文化这些影响网站内容质量的因素。

内容的产出应该由运营根据用户诉求、网站定位、圈子文化来进行创作。我们需要做好本职工作，让内容更好的被搜索引擎收录，提高网站的曝光率。

#### 1.2.1 如何才能将内容更好的被搜索引擎收录？

- keywords 关键词
- description 描述
- title 标题
- content 内容
- image 图片
- video 视频
- JSON-LD 结构化数据

我们都知道html的head头可以放一些元信息，这些元信息可以告诉搜索引擎一些关于该页面的信息。比如：关键词、描述、标题等。

```html
<head>
  <meta name="keywords" content="关键词1,关键词2,关键词3" />
  <meta name="description" content="描述" />
  <title>标题</title>
</head>
```

以上是html的head头可以放的一些元信息。我们可以通过这些元信息来告诉搜索引擎该页面的信息。

所以，凡是做SEO优化的页面，都应该在head头中放上这些元信息。而我们在日常开发中也需要关注这些元信息的维护。

#### 1.2.2 image 图片

图片是网页中重要的内容，搜索引擎可以通过图片的alt属性来了解图片的内容。所以，凡是做SEO优化的页面，都应该在图片的alt属性中放上图片的描述。

```html
<img src="xxx" alt="图片描述" />
```

以上是图片的alt属性可以放的一些元信息。我们可以通过这些元信息来告诉搜索引擎该图片的信息。而图片的地址更应该是语义化的，而不是hash值。目前海外项目部中，图片地址都是hash值😂。

#### 1.2.3 video 视频

视频是网页中的重要内容，且视频也会像网页一样被搜索引擎收录，编制索引。我们的海外站点，虽然不少页面都存在视频，且也被搜索引擎识别到，但是无法被编制索引，是因为没有专门的视频观看页。

这些视频都是商品卡片的头图，或者是商品分类的介绍。分散在各个页面。如果想要搜索引擎收录，则需要将这些视频集中到同一个页面，做一个视频播放页，类似Youtube。

视频地址也应该是语义化的，而不能用hash值。

#### 1.2.4 JSON-LD 结构化数据

JSON-LD 结构化数据是搜索引擎用来理解网页内容的重要方式。它是一种JSON格式的数据，其中包含网页的结构化信息。搜索引擎通过解析JSON-LD结构化数据来了解网页的结构和内容。

```json
<script type="application/ld+json">
  {
    "@context": "https://schema.org",
    "@type": "VideoObject",
    "name": "视频标题",
    "description": "视频描述",
    "thumbnailUrl": "https://www.example.com/video.jpg",
    "contentUrl": "https://www.example.com/video.mp4",
  }
</script>
```

像我们的海外站点，通过这些结构化数据可以将商品详情页的价格、物流时效、退货时效等关键信息直接展示在搜索结果页中，提高转化率。目前我们的海外站点中，wooacry是做了一段时间的结构化信息追踪，展示商品价格、商品评价这些关键信息。但是没有缺少了退货时效的信息和其他信息。

Acggoods 站点的商品详情页虽然也有结构化，但是缺少关注。不清楚信息展示是否正常。

#### 1.2.5 多语言-内容分发

多语言是搜索引擎优化中非常重要的一个环节。因为搜索引擎是基于关键词来检索的，而关键词是基于语言来区分的。所以，凡是做SEO优化的页面，都应该有对应的多语言版本。

但我们的海外站点虽然都做了多语言，其实没有专门做SEO优化。因为目前站点的多语言是通过cookie来区分，这种方案无法被搜索引擎识别。

最佳方案应该是通过路径来区分不同的语言版本。比如：

```html
<a href="https://www.example.com/en/page1">页面1</a>
<a href="https://www.example.com/zh/page1">页面1</a>
```

以上代码中，通过路径来区分不同的语言版本。搜索引擎通过抓取不同的路径来了解不同的语言版本。

这种方案对于人力成本和其他隐性成本来说，是比教划算的。域名的方式也能让搜索引擎更好的识别不同的语言版本，但是需要考虑相关备案等成本问题。

不过，目前我们的海外站点中大部分的流量都还是欧美，英语确实是主要的语言。

**总结**：SEO优化是一个长期的过程，而内容创造也是一个长期的过程。运营部分需要持续产出内容，而技术部分需要持续优化网页SEO，让内容更好的被搜索引擎收录，提高网站的曝光率。

我们目前的网站大部分的流量来源的关键词还是品牌名：`wooacry`、`acggoods`。所以，如果想要做其他关键词的优化，则需要挖掘圈子文化，找出关键词的搜索量、竞争程度、搜索意图等。然后再根据网站的定位、用户画像等信息来产出内容。

## 2. AI GEO

AI GEO是生成引擎优化（Generative Engine Optimization）的缩写。它是一种通过AI技术来优化搜索引擎排名的方式。它通过AI技术来分析网站内容，然后生成优化建议，帮助网站提高AI推荐排名。

### 2.1 从技术的视角理解AI GEO

- llm.txt/llm.md/llm-[language].txt
- 权威数据源：如新闻媒体站点、测评网站等
- 内容深度、结构化（偏向机器理解而不是人类理解）

### 2.2 我们适合做GEO吗

现如今做GEO的行业都是高利润率的行业，如：医美、律师、民生等。因为这些行业的投入产出比相对较高，可以承受GEO的投入成本。如今AI的发展日新月异，它这个模型可能偏爱采用xxx新闻的数据源、xxx测评网站的测评排行等。但下个模型的训练语料库发生改变，之前创作出来的内容可能就会毫无意义了。

### 2.3 如果要做，从技术层面应该如何做

- 做好每个商品的llm 信息优化
- 需要验证不同模型对内容结构的偏好，然后根据运营提供的内容创作来输出符合易于机器理解的结构内容。
- 需要打通各个社媒自动化发布渠道，实现自动化发布。
- 如有余力，可以做权威媒体站点，让不同的模型都偏好采用该站点内容。

如果想快速验证GEO对业务营收的影响，可以从买一些做GEO优化的服务，先看下效果。

## 3. 总结

GEO不是银弹，也不是黑科技，它是SEO的自然过渡。为了顺应AI时代下的信息获取，才催生的GEO概念。而SEO的很多优化技巧都可以适用在GEO的优化思路上。可以说GEO是建立在SEO基础上的一个优化方向，如果站点的SEO都做不好，何谈GEO。

国内做SEO --- 从我视角来看，投入产出相对较低。因为国内的生态是割裂的，每个大厂都想做超级APP，都想让用户把更多的时间放在自家的生态中。所以国内做SEO，不如多研究研究各个社媒平台的内容分发规则。比如，微信的公众号的搜索优化、抖音、小红书如何创作爆款内容等.

国内GEO的优化，也只能依托于各各大厂的生态。比如字节的豆包肯定是优先从抖音中搜索结果进而总结规划，展示给用户看。微信是公众号生态。所以，各个社媒平台的内容产出，出现的爆款越多，越能被各自厂商的模型所采用。
