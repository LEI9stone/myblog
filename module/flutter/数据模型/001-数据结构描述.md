# TypeScript Interface vs Dart Model Class

TypeScript 里常用 `interface` 描述数据结构：

```ts
interface Product {
  id: string;
  title: string;
  price: number;
}
```

Dart 里通常用 Model Class 表达同样的数据结构：

```dart
class Product {
  final String id;
  final String title;
  final double price;
}
```

两者都能描述“一个业务对象有哪些字段”，但 TypeScript interface 是编译期类型，Dart class 是真实的运行时代码。

可以这样映射：

| TypeScript Interface | Dart Model Class            |
| -------------------- | --------------------------- |
| `interface Product`  | `class Product`             |
| field declaration    | `final` field               |
| optional field `?`   | nullable field `T?`         |
| readonly field       | `final` field               |
| method signature     | class method                |
| structural typing    | nominal typing              |
| compile-time only    | runtime class               |
| object literal       | class instance              |
| JSON DTO shape       | `fromJson` / `toJson` model |
| utility types        | `copyWith` / Freezed        |

---

## 1. TypeScript Interface

```ts
interface Product {
  id: string;
  title: string;
  price: number;
  imageUrl?: string;
}
```

使用：

```ts
const product: Product = {
  id: '1',
  title: 'Cup',
  price: 99,
};
```

在 TypeScript 中，只要对象结构符合 `Product`，就可以当作 `Product` 使用。

这叫：

```text
structural typing
```

---

## 2. Dart Model Class

```dart
class Product {
  const Product({
    required this.id,
    required this.title,
    required this.price,
    this.imageUrl,
  });

  final String id;
  final String title;
  final double price;
  final String? imageUrl;
}
```

使用：

```dart
const product = Product(
  id: '1',
  title: 'Cup',
  price: 99,
);
```

Dart 是名义类型：

```text
必须是 Product 实例，才是 Product。
```

不能随便拿一个 Map 当 Product 用。

---

## 3. Optional Field vs Nullable Field

TypeScript：

```ts
interface Product {
  imageUrl?: string;
}
```

Dart：

```dart
final String? imageUrl;
```

Dart 没有 `undefined`，所以：

```text
字段缺失
字段为 null
```

通常都会被映射成：

```dart
null
```

---

## 4. readonly vs final

TypeScript：

```ts
interface Product {
  readonly id: string;
}
```

Dart：

```dart
final String id;
```

`final` 表示字段只能赋值一次。

但注意，如果字段是 List：

```dart
final List<String> tags;
```

`final` 只限制 `tags` 不能指向另一个 List，不代表 List 内容不能被修改。

---

## 5. JSON 转换

TypeScript：

```ts
const product = (await response.json()) as Product;
```

这只是类型断言，不会运行时校验。

Dart：

```dart
factory Product.fromJson(Map<String, dynamic> json) {
  return Product(
    id: json['id'] as String,
    title: json['title'] as String,
    price: (json['price'] as num).toDouble(),
    imageUrl: json['imageUrl'] as String?,
  );
}
```

实际项目更常用：

```text
json_serializable
freezed
```

生成 fromJson/toJson。

---

## 6. Freezed 写法

```dart
@freezed
abstract class Product with _$Product {
  const factory Product({
    required String id,
    required String title,
    required double price,
    String? imageUrl,
  }) = _Product;

  factory Product.fromJson(Map<String, dynamic> json) =>
      _$ProductFromJson(json);
}
```

它更接近 TypeScript DTO + immutable model 的开发体验，并额外生成：

```text
copyWith
==
hashCode
toJson/fromJson
```

---

## 7. 核心差异

TypeScript：

```text
interface 描述对象形状；
运行时没有 interface；
普通 object 只要结构匹配即可。
```

Dart：

```text
class 定义真实类型；
运行时有 class 实例；
类型匹配基于类名和继承/实现关系。
```

一句话理解：

```text
TypeScript Interface 是编译期的结构类型描述；
Dart Model Class 是运行时存在的名义类型对象。
从 Web 迁移到 Flutter 时，接口返回的 plain object 通常要转成 Dart model class。
```
