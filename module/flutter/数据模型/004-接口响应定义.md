# JSON DTO vs Domain Model

JSON DTO 是“接口返回/提交的数据形状”。

Domain Model 是“App 业务内部真正使用的模型”。

两者可以一样，但在复杂业务里最好分开。

| 概念         | 作用                          |
| ------------ | ----------------------------- |
| JSON DTO     | 贴近后端接口结构              |
| Domain Model | 贴近前端业务语义              |
| Mapper       | 负责 DTO 和 Domain Model 转换 |

---

## 1. Web 中的常见情况

TypeScript 里经常直接把接口 DTO 当业务类型用：

```ts
type ProductDto = {
  product_id: string;
  title: string;
  price_cent: number;
};
```

业务里可能直接使用：

```ts
product.product_id;
product.price_cent;
```

小项目可以这样，但业务复杂后会让接口细节渗透到 UI。

---

## 2. Flutter 中的推荐分层

DTO：

```dart
class ProductDto {
  const ProductDto({
    required this.productId,
    required this.title,
    required this.priceCent,
  });

  final String productId;
  final String title;
  final int priceCent;
}
```

Domain Model：

```dart
class Product {
  const Product({
    required this.id,
    required this.title,
    required this.price,
  });

  final String id;
  final String title;
  final Decimal price;
}
```

Mapper：

```dart
extension ProductDtoMapper on ProductDto {
  Product toDomain() {
    return Product(
      id: productId,
      title: title,
      price: Decimal.fromInt(priceCent) / Decimal.fromInt(100),
    );
  }
}
```

---

## 3. 为什么要分开

DTO 贴近接口：

```text
字段名可能是 snake_case
金额可能是分
状态可能是后端枚举字符串
字段可能有 null/缺失
可能包含 UI 不需要的字段
```

Domain Model 贴近业务：

```text
字段名更符合 App 语义
金额类型更安全
状态用 enum/sealed class
隐藏后端历史包袱
UI 不依赖接口细节
```

---

## 4. Repository 负责转换

推荐数据流：

```text
API Response JSON
→ ProductDto.fromJson
→ ProductDto.toDomain()
→ Product
→ UI / Provider
```

Repository 示例：

```dart
Future<List<Product>> fetchProducts() async {
  final response = await api.fetchProducts();

  return response
      .map((json) => ProductDto.fromJson(json).toDomain())
      .toList();
}
```

这样 UI 只接触 `Product`，不接触 `ProductDto`。

---

## 5. 什么时候可以不分

可以 DTO = Domain Model：

```text
项目很小
接口字段非常稳定
字段命名和业务模型一致
没有金额/状态/时间等转换
没有离线缓存或多数据源
```

建议分开：

```text
接口字段和 UI 语义不一致
需要金额、时间、枚举转换
后端结构经常变化
同一个业务模型来自多个接口
需要本地缓存/数据库模型
需要降低 UI 对接口结构的耦合
```

一句话理解：

```text
JSON DTO 服务接口边界；
Domain Model 服务 App 业务语义。
简单项目可以合并，
复杂业务建议在 Repository 层把 DTO 转成 Domain Model，再交给 UI 使用。
```
