# Global Error Toast vs `ScaffoldMessenger` / Dialog

Web 里全局错误提示常用 Toast：

```text
toast.error('保存失败')
message.error('网络异常')
notification.error(...)
```

Flutter 中对应常见是：

```dart
ScaffoldMessenger
SnackBar
Dialog
showDialog
showModalBottomSheet
```

可以这样映射：

| Web Global Error Toast | Flutter                          |
| ---------------------- | -------------------------------- |
| toast                  | `SnackBar`                       |
| message                | `ScaffoldMessenger.showSnackBar` |
| notification           | `SnackBar` / Dialog / Banner     |
| modal error            | `showDialog`                     |
| confirm dialog         | `AlertDialog`                    |
| global error handler   | `ref.listen` / error service     |
| form submit error      | SnackBar / field error           |
| blocking error         | Dialog                           |
| non-blocking error     | SnackBar                         |

---

## 1. Web Global Toast

Web：

```ts
toast.error('保存失败，请稍后重试');
```

通常用于：

```text
提交失败
网络异常
保存成功/失败
轻量提示
不打断用户流程
```

---

## 2. Flutter SnackBar

Flutter 中最常见的是：

```dart
ScaffoldMessenger.of(context).showSnackBar(
  const SnackBar(
    content: Text('保存失败，请稍后重试'),
  ),
);
```

它类似 Web 的 toast/message。

如果要先清掉旧提示：

```dart
ScaffoldMessenger.of(context)
  ..clearSnackBars()
  ..showSnackBar(
    const SnackBar(
      content: Text('保存失败，请稍后重试'),
    ),
  );
```

---

## 3. ScaffoldMessenger 的作用

`SnackBar` 需要通过 `ScaffoldMessenger` 显示：

```dart
ScaffoldMessenger.of(context)
```

它会找到当前 `Scaffold` 所在的消息展示区域。

常见使用场景：

```text
按钮提交失败
刷新失败
复制成功
删除成功
网络异常提示
```

---

## 4. Dialog

如果错误需要用户明确确认，或者会阻断流程，用 Dialog：

```dart
showDialog(
  context: context,
  builder: (context) {
    return AlertDialog(
      title: const Text('操作失败'),
      content: const Text('订单提交失败，请稍后重试。'),
      actions: [
        TextButton(
          onPressed: () => Navigator.of(context).pop(),
          child: const Text('确定'),
        ),
      ],
    );
  },
);
```

适合：

```text
支付失败
权限不足
危险操作失败
需要用户确认的业务错误
会影响当前流程继续的错误
```

---

## 5. SnackBar vs Dialog 怎么选

| 错误类型             | 推荐                    |
| -------------------- | ----------------------- |
| 轻量提示             | `SnackBar`              |
| 不阻断流程           | `SnackBar`              |
| 提交失败但可继续编辑 | `SnackBar`              |
| 需要用户确认         | `Dialog`                |
| 权限/登录失效        | Dialog 或跳登录         |
| 页面加载失败         | `ErrorView`             |
| 表单字段错误         | 字段 validator          |
| 加载更多失败         | footer error / SnackBar |

---

## 6. Riverpod 中监听错误

不要在 `build()` 里直接弹 SnackBar。更推荐用监听：

```dart
ref.listen(submitProvider, (previous, next) {
  if (next case AsyncError(:final error)) {
    ScaffoldMessenger.of(context).showSnackBar(
      SnackBar(content: Text('$error')),
    );
  }
});
```

这样 UI 构建和副作用分开。

---

## 7. 页面错误 vs 全局提示

区分两类错误：

```text
页面主数据加载失败 → ErrorView
用户操作失败 → SnackBar/Dialog
```

例如商品详情加载失败：

```dart
ErrorView(
  error: error,
  onRetry: reload,
)
```

收藏商品失败：

```dart
ScaffoldMessenger.of(context).showSnackBar(
  const SnackBar(content: Text('收藏失败')),
);
```

一句话理解：

```text
Web 的 Global Error Toast 在 Flutter 中通常对应 SnackBar + ScaffoldMessenger；
轻量、不阻断的错误用 SnackBar，
需要用户确认或阻断流程的错误用 Dialog，
页面级加载失败用 ErrorView。
```
