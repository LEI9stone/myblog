# `try/catch` vs Dart Exception Handling

JavaScript/TypeScript 和 Dart 都支持 `try/catch/finally`。

区别在于 Dart 支持更明确的类型化捕获：

```dart
on SomeException catch (error)
```

并且可以同时拿到：

```dart
error
stackTrace
```

可以这样映射：

| JavaScript / TypeScript | Dart                                   |
| ----------------------- | -------------------------------------- |
| `try/catch`             | `try/catch`                            |
| `catch (error)`         | `catch (error, stackTrace)`            |
| `finally`               | `finally`                              |
| `throw new Error()`     | `throw Exception()` / 自定义 Exception |
| `error instanceof X`    | `on X catch (error)`                   |
| async error             | Future error                           |
| Promise reject          | Future error                           |
| rethrow                 | `rethrow`                              |
| custom Error            | custom Exception class                 |

---

## 1. 基本 try/catch

TypeScript：

```ts
try {
  await submit();
} catch (error) {
  console.error(error);
}
```

Dart：

```dart
try {
  await submit();
} catch (error, stackTrace) {
  debugPrint('$error');
}
```

`stackTrace` 可用于：

```text
日志
错误上报
调试定位
```

---

## 2. 类型化捕获

TypeScript：

```ts
try {
  await request();
} catch (error) {
  if (error instanceof ApiError) {
    // handle API error
  }
}
```

Dart：

```dart
try {
  await request();
} on ApiException catch (error) {
  // handle API error
} on FormatException catch (error) {
  // handle parse error
} catch (error) {
  // fallback
}
```

心智映射：

```text
TS: catch 后用 instanceof 分支
Dart: 用 on XxxException catch 分支
```

---

## 3. finally

TypeScript：

```ts
try {
  setLoading(true);
  await submit();
} finally {
  setLoading(false);
}
```

Dart：

```dart
try {
  setLoading(true);
  await submit();
} finally {
  setLoading(false);
}
```

适合：

```text
关闭 loading
释放资源
恢复按钮状态
清理临时变量
```

---

## 4. throw

TypeScript：

```ts
throw new Error('Submit failed');
```

Dart：

```dart
throw Exception('Submit failed');
```

更推荐业务自定义异常：

```dart
class ApiException implements Exception {
  const ApiException(this.message);

  final String message;

  @override
  String toString() => message;
}
```

抛出：

```dart
throw const ApiException('Submit failed');
```

---

## 5. rethrow

如果捕获后只做日志，再继续抛出原异常：

```dart
try {
  await request();
} catch (error, stackTrace) {
  logger.error(error, stackTrace);
  rethrow;
}
```

`rethrow` 会保留原始异常上下文，比 `throw error` 更适合这种场景。

---

## 6. async/await 异常

TypeScript：

```ts
async function load() {
  throw new Error('failed');
}
```

调用方：

```ts
try {
  await load();
} catch (error) {}
```

Dart：

```dart
Future<void> load() async {
  throw Exception('failed');
}
```

调用方：

```dart
try {
  await load();
} catch (error) {}
```

异步错误会通过 `Future` 传播，被 `await` 处的 `catch` 捕获。

---

## 7. Exception vs Error

Dart 中通常这样区分：

| 类型        | 含义                           |
| ----------- | ------------------------------ |
| `Exception` | 可预期、可处理的异常           |
| `Error`     | 程序错误、断言失败、类型错误等 |

业务代码通常抛：

```dart
Exception
```

不要随便抛：

```dart
Error
```

例如接口失败、解析失败、业务校验失败更适合自定义 `Exception`。

## 8. Flutter/Riverpod 中的处理

Repository 层：

```dart
Future<Product> fetchProduct() async {
  try {
    final response = await dio.get('/product');
    return Product.fromJson(response.data);
  } on DioException catch (error) {
    throw ApiException.fromDio(error);
  }
}
```

Provider 层：

```dart
state = await AsyncValue.guard(() {
  return repository.fetchProduct();
});
```

UI 层：

```dart
switch (state) {
  case AsyncError(:final error):
    return ErrorView(error: error);
  // ...
}
```

---

一句话理解：

```text
JavaScript/TypeScript 和 Dart 都用 try/catch/finally；
Dart 更常用 on XxxException catch 做类型化捕获，
catch 可以同时拿到 error 和 stackTrace。
业务异常用 Exception，
程序级错误通常属于 Error。
```
