# Retry UI vs Reload Callback

Web 里错误态通常会提供“重试”按钮：

```tsx
<ErrorView onRetry={refetch} />
```

Flutter 中对应是：

```dart
ErrorView(onRetry: reload)
```

重试本质上是把 reload/refetch callback 从状态层传给 UI。

可以这样映射：

| Web Retry UI          | Flutter                          |
| --------------------- | -------------------------------- |
| Retry button          | Button / AppButton               |
| `onRetry` prop        | `VoidCallback onRetry`           |
| React Query `refetch` | `ref.invalidate` / `ref.refresh` |
| reload function       | Notifier `reload()`              |
| error component       | `ErrorView`                      |
| retry loading         | AsyncLoading / button loading    |
| stale data retry      | keep data + show snackbar        |
| pull to refresh       | `RefreshIndicator.onRefresh`     |

---

## 1. Web Retry UI

React：

```tsx
<ErrorView title="加载失败" onRetry={() => refetch()} />
```

ErrorView 内部：

```tsx
<button onClick={onRetry}>重试</button>
```

核心是：

```text
错误 UI 不负责知道怎么请求；
它只调用外部传入的 onRetry。
```

---

## 2. Flutter ErrorView

```dart
class ErrorView extends StatelessWidget {
  const ErrorView({
    super.key,
    required this.message,
    required this.onRetry,
  });

  final String message;
  final VoidCallback onRetry;

  @override
  Widget build(BuildContext context) {
    return Center(
      child: Column(
        mainAxisSize: MainAxisSize.min,
        children: [
          Text(message),
          ElevatedButton(
            onPressed: onRetry,
            child: const Text('重试'),
          ),
        ],
      ),
    );
  }
}
```

使用：

```dart
ErrorView(
  message: '加载失败',
  onRetry: () {
    ref.invalidate(productsProvider);
  },
)
```

## 3. FutureProvider 重试

```dart
final products = ref.watch(productsProvider);

switch (products) {
  case AsyncError():
    return ErrorView(
      message: '加载失败',
      onRetry: () {
        ref.invalidate(productsProvider);
      },
    );
  // ...
}
```

也可以：

```dart
ref.refresh(productsProvider);
```

简单理解：

| 操作                       | 含义                            |
| -------------------------- | ------------------------------- |
| `ref.invalidate(provider)` | 标记失效，下次/当前监听重新计算 |
| `ref.refresh(provider)`    | 立即刷新并返回新值              |

UI 重试通常用 `invalidate` 就够清晰。

---

## 4. AsyncNotifier 重试

如果是 `AsyncNotifier`：

```dart
ErrorView(
  message: '加载失败',
  onRetry: () {
    ref.read(productListProvider.notifier).reload();
  },
)
```

Notifier：

```dart
Future<void> reload() async {
  state = const AsyncLoading();

  state = await AsyncValue.guard(() async {
    final repository = ref.read(productRepositoryProvider);
    return repository.fetchProducts();
  });
}
```

---

## 5. 重试时的 Loading 表现

首屏失败后重试：

```text
点击重试 → 显示 LoadingView → 成功显示内容 / 失败显示 ErrorView
```

已有数据刷新失败：

```text
保留旧数据 → 显示 snackbar → 用户可再次重试
```

不要所有 retry 都清空页面，具体看业务场景。

---

## 6. Pull to Refresh

Flutter 下拉刷新：

```dart
RefreshIndicator(
  onRefresh: () async {
    ref.invalidate(productsProvider);
  },
  child: ProductList(products: products),
)
```

如果要等待刷新完成，通常使用 notifier 的 async 方法更好：

```dart
onRefresh: () {
  return ref.read(productListProvider.notifier).reload();
}
```

---

## 7. 设计原则

ErrorView 应该是纯展示组件：

```text
展示错误信息
展示重试按钮
调用 onRetry
```

不应该：

```text
直接调 repository
直接知道 provider 名字
自己处理复杂业务状态
```

让页面或 Notifier 决定 reload 行为。

---

一句话理解：

```text
Retry UI 是错误态里的用户操作入口；
Reload Callback 是真正重新请求数据的函数。
Flutter 中通常由 ErrorView 暴露 onRetry，
页面传入 ref.invalidate(provider) 或 notifier.reload()。
```
