# Browser Permissions vs Native Permissions

Web 里浏览器负责权限模型，比如定位、通知、摄像头、麦克风。

Flutter iOS/Android 中权限由操作系统管理，需要同时处理：

```text
平台配置声明
运行时权限请求
用户拒绝/永久拒绝
权限状态变化
```

可以这样映射：

| Browser Permissions     | Native Permissions                  |
| ----------------------- | ----------------------------------- |
| `navigator.permissions` | permission plugin                   |
| Geolocation permission  | location permission                 |
| Notification permission | push notification permission        |
| Camera permission       | camera permission                   |
| Microphone permission   | microphone permission               |
| Clipboard permission    | platform clipboard rules            |
| browser prompt          | OS permission dialog                |
| HTTPS requirement       | platform manifest/plist requirement |
| permission denied       | denied / permanentlyDenied          |
| site settings           | app settings                        |

---

## 1. Web Permissions

Web：

```ts
navigator.geolocation.getCurrentPosition(...)
```

浏览器会弹出权限提示：

```text
允许
拒绝
```

部分 API 需要：

```text
HTTPS
用户手势
浏览器支持
站点权限设置
```

---

## 2. Native Permissions

Flutter 移动端权限通常需要两步：

```text
1. 平台文件声明权限用途
2. 运行时请求权限
```

例如相机：

Android：

```xml
<uses-permission android:name="android.permission.CAMERA" />
```

iOS：

```xml
NSCameraUsageDescription
```

然后 Dart 侧用插件请求权限。

---

## 3. permission_handler

Flutter 常用：

```text
permission_handler
```

示例：

```dart
final status = await Permission.camera.request();

if (status.isGranted) {
  // use camera
} else if (status.isPermanentlyDenied) {
  openAppSettings();
}
```

常见状态：

```text
granted
denied
permanentlyDenied
restricted
limited
```

---

## 4. Info.plist / AndroidManifest

iOS 必须写权限用途描述，否则可能崩溃或审核不过。

例如：

```text
NSCameraUsageDescription
NSPhotoLibraryUsageDescription
NSLocationWhenInUseUsageDescription
NSMicrophoneUsageDescription
```

Android 需要在：

```text
AndroidManifest.xml
```

声明权限。

新版本 Android 还会细分：

```text
照片/视频权限
通知权限
定位前台/后台
蓝牙权限
```

---

## 5. 权限 UX

不要一打开 App 就请求一堆权限。

更推荐：

```text
用户触发相关功能时再请求
先说明为什么需要
被拒绝后提供替代流程
永久拒绝后引导去系统设置
```

例如：

```text
点击“拍照上传”时请求相机权限
点击“定位附近门店”时请求定位权限
```

---

## 6. Web 和 Native 的关键差异

Web：

```text
浏览器统一管理权限
权限通常按站点维度
用户可在浏览器设置里改
```

Native：

```text
操作系统管理权限
权限按 App 维度
需要平台配置 + 运行时请求
审核也会关注权限用途
```

---

## 7. 常见权限映射

| 能力   | Web                    | Flutter                                  |
| ------ | ---------------------- | ---------------------------------------- |
| 定位   | Geolocation API        | geolocator / permission_handler          |
| 相机   | MediaDevices           | camera / image_picker                    |
| 麦克风 | MediaDevices           | permission_handler / recorder plugin     |
| 通知   | Notification API       | firebase_messaging / local_notifications |
| 相册   | file input / picker    | image_picker / photo_manager             |
| 文件   | File System Access API | file_picker / path_provider              |
| 剪贴板 | Clipboard API          | Clipboard service                        |
| 蓝牙   | Web Bluetooth          | flutter_blue_plus 等插件                 |

---

一句话理解：

```text
Browser Permissions 是浏览器按站点管理的权限；
Native Permissions 是 iOS/Android 按 App 管理的权限。
Flutter 中既要在平台配置文件声明权限，
又要在运行时请求权限，并处理拒绝、永久拒绝和跳转系统设置。
```
