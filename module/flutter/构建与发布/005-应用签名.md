# App Signing vs Web Deployment

Web Deployment 通常是把构建产物上传到服务器或 CDN。

App Signing 是移动端发布前必须做的签名流程，用来证明这个 App 是由可信开发者发布，并保证后续更新来自同一身份。

可以这样映射：

| Web Deployment  | App Signing                    |
| --------------- | ------------------------------ |
| 上传 `dist/`    | 签名 APK/AAB/IPA               |
| CDN / Server    | App Store / Play Store         |
| HTTPS 证书      | 开发者证书 / keystore          |
| 域名所有权      | Bundle ID / Application ID     |
| deploy key      | signing certificate / keystore |
| source maps     | debug symbols / dSYM           |
| rollback deploy | 商店版本回滚较复杂             |
| 发布后刷新生效  | 用户安装/更新 App              |

---

## 1. Web Deployment

Web：

```bash
npm run build
```

输出：

```text
dist/
```

部署到：

```text
Nginx
CDN
Vercel
Netlify
S3
Cloudflare Pages
```

用户访问 URL 获取最新资源。

核心关注：

```text
缓存策略
CDN 刷新
环境变量
source map
回滚
HTTPS
```

---

## 2. App Signing

Flutter 移动端构建发布包前需要签名。

Android：

```text
keystore
key alias
key password
store password
AAB/APK signing
```

iOS：

```text
Apple Developer certificate
Provisioning Profile
Bundle ID
Team ID
App Store signing
```

没有正确签名，App 不能正常发布或安装到目标渠道。

---

## 3. Android Signing

Android 发布通常构建：

```bash
flutter build appbundle --release
```

签名配置涉及：

```text
android/key.properties
android/app/build.gradle
keystore 文件
```

产物：

```text
.aab  用于 Google Play
.apk  可用于直接安装/内部分发
```

签名身份必须稳定，否则用户无法从旧版本平滑升级。

---

## 4. iOS Signing

iOS 签名涉及：

```text
Bundle Identifier
Certificate
Provisioning Profile
Entitlements
App Store Connect
```

Flutter 构建：

```bash
flutter build ipa --release
```

实际经常需要 Xcode 或 fastlane 配合。

iOS 签名通常比 Web 部署复杂，CI 中要管理证书和 profile。

---

## 5. 和 HTTPS 证书的类比

Web HTTPS 证书证明：

```text
这个域名的连接可信
```

App signing 证明：

```text
这个 App 包来自某个开发者身份
后续更新来自同一个签名身份
包没有被篡改
```

类比可以帮助理解，但二者不是同一种机制。

---

## 6. 密钥安全

Web 部署密钥不能泄露。

App signing key 更不能泄露：

```text
Android keystore
Apple certificate
Provisioning profile
CI signing secrets
```

泄露后可能导致：

```text
恶意包签名
发布链路风险
更新身份风险
需要复杂的密钥轮换
```

不要提交到 Git 仓库。

---

## 7. 发布回滚差异

Web：

```text
部署旧 dist 即可快速回滚
```

移动 App：

```text
用户设备已经安装新版本
应用商店审核和版本传播有延迟
回滚不如 Web 直接
```

所以 App 发布更依赖：

```text
灰度
feature flag
远程配置
兼容性
崩溃监控
快速补丁版本
```

---

一句话理解：

```text
Web Deployment 是把构建产物发布到服务器/CDN；
App Signing 是移动端发布包进入商店或安装前的身份签名流程。
Web 关注部署和缓存，
App 还必须关注签名证书、keystore、Bundle ID、商店审核和版本升级身份。
```
