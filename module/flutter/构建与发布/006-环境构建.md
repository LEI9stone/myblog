# 环境构建

Web 里常用环境构建区分：

```text
development
staging
production
```

Flutter 里对应常见是：

```text
Flavor
dart-define
环境配置文件
不同平台 Bundle ID / Application ID
```

可以这样映射：

| Web Environment Build   | Flutter Flavor                        |
| ----------------------- | ------------------------------------- |
| `.env.development`      | dev flavor                            |
| `.env.staging`          | staging flavor                        |
| `.env.production`       | prod flavor                           |
| `NODE_ENV` / mode       | `APP_ENV` / flavor                    |
| `VITE_API_URL`          | `--dart-define=API_BASE_URL=...`      |
| different deploy target | different app variant                 |
| staging domain          | staging API config                    |
| prod domain             | prod API config                       |
| preview build           | dev/staging flavor build              |
| build mode              | debug/profile/release，和 flavor 不同 |

---

## 1. Web Environment Build

Web：

```bash
npm run build -- --mode staging
```

Vite：

```text
.env.development
.env.staging
.env.production
```

代码中读取：

```ts
import.meta.env.VITE_API_BASE_URL;
```

环境构建通常影响：

```text
API 地址
功能开关
埋点环境
Sentry DSN
构建优化模式
部署目标
```

---

## 2. Flutter Flavor

Flutter flavor 用来区分不同 App 变体：

```text
dev
staging
prod
```

常见命令：

```bash
flutter run --flavor dev
flutter run --flavor staging
flutter run --flavor prod
```

构建：

```bash
flutter build apk --flavor prod
flutter build appbundle --flavor prod
flutter build ios --flavor prod
```

Flavor 通常会影响：

```text
App 名称
Bundle ID / Application ID
图标
平台配置
后端环境
第三方 SDK 配置
```

---

## 3. dart-define

Flutter Dart 层环境变量通常用：

```bash
--dart-define
```

例如：

```bash
flutter run \
  --flavor staging \
  --dart-define=APP_ENV=staging \
  --dart-define=API_BASE_URL=https://staging-api.example.com
```

代码中：

```dart
class AppConfig {
  static const appEnv = String.fromEnvironment(
    'APP_ENV',
    defaultValue: 'dev',
  );

  static const apiBaseUrl = String.fromEnvironment(
    'API_BASE_URL',
    defaultValue: 'https://dev-api.example.com',
  );
}
```

---

## 4. Flavor 和 Build Mode 不是一回事

Flutter build mode：

```text
debug
profile
release
```

Flavor：

```text
dev
staging
prod
```

它们是两个维度。

例如：

```bash
flutter run --flavor staging --debug
flutter build appbundle --flavor prod --release
```

含义不同：

| 维度       | 控制                         |
| ---------- | ---------------------------- |
| build mode | 编译优化、调试能力、性能模式 |
| flavor     | 环境、包名、配置、API 地址   |

---

## 5. 平台配置差异

Android flavor 可能对应：

```text
applicationIdSuffix
resValue app_name
不同 google-services.json
```

iOS flavor 可能对应：

```text
不同 scheme
不同 bundle identifier
不同 xcconfig
不同 GoogleService-Info.plist
```

这些是 Web 环境构建里通常没有的复杂度。

---

## 6. 推荐组合

常见策略：

```text
dev flavor + dev API + debug
staging flavor + staging API + release/profile
prod flavor + prod API + release
```

示例：

```bash
flutter build appbundle \
  --flavor prod \
  --release \
  --dart-define=APP_ENV=prod \
  --dart-define=API_BASE_URL=https://api.example.com
```

---

## 7. 不要把敏感信息放进 dart-define

和 Web `.env` 一样，客户端环境变量不是安全密钥库。

不要放：

```text
后端 secret
私钥
支付 secret
管理员 token
```

可以放：

```text
API base URL
APP_ENV
公开 app id
Sentry DSN
feature flag 默认值
```

一句话理解：

```text
Web Environment Build 用 .env/mode 区分 dev/staging/prod；
Flutter 用 flavor 区分 App 变体和平台配置，
用 dart-define 注入 Dart 层环境变量。
Flavor 和 debug/profile/release build mode 是两个不同维度。
```
