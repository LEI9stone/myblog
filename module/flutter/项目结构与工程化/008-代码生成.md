# Codegen：前端代码生成 vs Flutter build_runner

Web 前端里的代码生成通常分散在不同工具里，比如 OpenAPI 生成 API Client、GraphQL 生成类型、路由生成、icon 生成、schema 类型生成等。

Flutter/Dart 里，常见代码生成统一由 `build_runner` 驱动，再配合不同 generator 包生成 `.g.dart`、`.freezed.dart` 等文件。

可以这样映射：

| Web                    | Flutter / Dart                                   |
| ---------------------- | ------------------------------------------------ |
| OpenAPI Generator      | retrofit_generator / swagger_dart_code_generator |
| GraphQL Codegen        | graphql_codegen                                  |
| Zod schema 推导类型    | json_serializable / freezed                      |
| Prisma Client Generate | drift_dev / build_runner                         |
| 路由生成               | go_router_builder                                |
| i18n 生成              | gen_l10n / intl tooling                          |
| Icon 生成              | flutter_gen / build_runner                       |
| `npm run codegen`      | `dart run build_runner build`                    |
| watch mode             | `dart run build_runner watch`                    |

---

## 1. build_runner 是什么

可以把 `build_runner` 理解成 Dart 生态里的“代码生成任务执行器”。

它本身通常不负责具体生成逻辑，而是负责扫描项目、执行 generator、输出生成文件。

类似 Web 里的：

```text
codegen command runner
```

实际生成能力来自不同包：

| 需求              | 常见 Flutter 工具    |
| ----------------- | -------------------- |
| JSON 序列化       | `json_serializable`  |
| 不可变模型        | `freezed`            |
| 数据库代码        | `drift_dev`          |
| Riverpod Provider | `riverpod_generator` |
| 路由              | `go_router_builder`  |
| Retrofit API      | `retrofit_generator` |
| 资源引用          | `flutter_gen_runner` |

---

## 2. 常见生成文件

Flutter/Dart 项目里常见：

```text
*.g.dart
*.freezed.dart
*.gr.dart
```

例如：

```text
product_model.dart
product_model.g.dart
product_model.freezed.dart
```

通常源文件里会写：

```dart
part 'product_model.freezed.dart';
part 'product_model.g.dart';
```

含义类似：

```text
当前文件声明一部分代码；
生成文件补齐另一部分代码；
编译时共同组成一个 library。
```

---

## 3. 常用命令

一次性生成：

```bash
dart run build_runner build
```

持续监听生成：

```bash
dart run build_runner watch
```

处理冲突输出：

```bash
dart run build_runner build --delete-conflicting-outputs
```

对应 Web：

```bash
npm run codegen
npm run codegen:watch
```

---

## 4. 和 Web 代码生成的差异

Web 中代码生成可能是多个独立命令：

```bash
openapi-generator-cli generate
graphql-codegen
prisma generate
```

Flutter 中很多 generator 都接入 `build_runner`：

```bash
dart run build_runner build
```

它会一次执行项目中已配置的多个 generator，例如：

```text
freezed
json_serializable
riverpod_generator
drift_dev
```

---

## 5. 当前项目中的典型例子

从依赖看，这类 Flutter 项目通常会用到：

```yaml
dev_dependencies: build_runner
  riverpod_generator
  freezed
  json_serializable
  drift_dev
```

对应生成内容大致是：

| 依赖                 | 生成内容                           |
| -------------------- | ---------------------------------- |
| `riverpod_generator` | Provider 相关代码                  |
| `freezed`            | 不可变模型、copyWith、union/sealed |
| `json_serializable`  | JSON 序列化/反序列化               |
| `drift_dev`          | 数据库表、DAO、查询代码            |

---

## 6. 生成文件是否提交

通常 Flutter 项目会提交生成文件，例如：

```text
*.g.dart
*.freezed.dart
```

原因是：

```text
CI、IDE、代码审查、构建流程更稳定；
使用方不一定每次都自动生成。
```

但具体是否提交，取决于团队约定。

---

一句话理解：

```text
Web 前端代码生成通常由多个工具各自执行；
Flutter/Dart 里常见代码生成统一通过 build_runner 调度，
由 freezed、json_serializable、riverpod_generator、drift_dev 等 generator 生成配套 Dart 文件。
```
