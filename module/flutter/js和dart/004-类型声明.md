# Interface/Type Alias vs Class/Abstract Class/Extension

TypeScript 常用 `interface` 和 `type` 描述数据形状、函数签名、联合类型和类型别名。

Dart 没有 TypeScript 那种结构化 `interface`，更常用 `class`、`abstract class`、`typedef`、`extension` 来表达类型和能力。

| TypeScript          | Dart                                |
| ------------------- | ----------------------------------- |
| `interface`         | `class` / `abstract class`          |
| `type` alias        | `typedef`                           |
| object shape        | class model                         |
| function type alias | typedef                             |
| union type          | sealed class / enum / Freezed       |
| interface extends   | abstract class implements / extends |
| declaration merging | 无直接等价                          |
| extension method    | extension                           |

---

## 1. `interface` vs `class`

TypeScript：

```ts
interface Product {
  id: string;
  title: string;
  price: number;
}
```

Dart 通常写成：

```dart
class Product {
  final String id;
  final String title;
  final double price;

  const Product({
    required this.id,
    required this.title,
    required this.price,
  });
}
```

核心差异：

```text
TypeScript interface 描述对象“长什么样”；
Dart class 定义一个具体类型。
```

TypeScript 是结构类型：

```ts
const item = {
  id: '1',
  title: 'Cup',
  price: 99,
};

const product: Product = item;
```

只要结构匹配就可以。

Dart 是名义类型：

```dart
final item = Product(
  id: '1',
  title: 'Cup',
  price: 99,
);
```

通常必须创建对应 class 的实例。

## 2. `interface` 用于抽象能力

TypeScript：

```ts
interface ProductRepository {
  fetchProducts(): Promise<Product[]>;
}
```

Dart 通常用 `abstract class`：

```dart
abstract class ProductRepository {
  Future<List<Product>> fetchProducts();
}
```

实现：

```dart
class RemoteProductRepository implements ProductRepository {
  @override
  Future<List<Product>> fetchProducts() async {
    // ...
  }
}
```

映射关系：

```text
TS interface 作为契约
≈ Dart abstract class 作为契约
```

## 3. `type` alias vs `typedef`

TypeScript：

```ts
type ProductId = string;

type OnSubmit = (value: string) => void;
```

Dart：

```dart
typedef ProductId = String;

typedef OnSubmit = void Function(String value);
```

常见用途：

```text
给复杂类型起名字
声明函数签名
提升代码可读性
```

## 4. `type` union vs Dart sealed class

TypeScript：

```ts
type LoadState =
  | { type: 'loading' }
  | { type: 'success'; data: Product[] }
  | { type: 'error'; message: string };
```

Dart：

```dart
sealed class LoadState {}

class Loading extends LoadState {}

class Success extends LoadState {
  final List<Product> data;
  Success(this.data);
}

class Failure extends LoadState {
  final String message;
  Failure(this.message);
}
```

Flutter 项目中也常用 Freezed：

```dart
@freezed
sealed class LoadState with _$LoadState {
  const factory LoadState.loading() = Loading;
  const factory LoadState.success(List<Product> data) = Success;
  const factory LoadState.error(String message) = Failure;
}
```

## 5. Extension

TypeScript 可以通过工具函数或 prototype 扩展能力，但前端业务里更常见的是普通函数：

```ts
function formatPrice(value: number) {
  return `¥${value.toFixed(2)}`;
}
```

Dart 有正式的 `extension`：

```dart
extension PriceFormat on num {
  String toPriceText() {
    return '¥${toStringAsFixed(2)}';
  }
}
```

使用：

```dart
final text = 99.8.toPriceText();
```

可以理解为：

```text
Dart extension 用来给已有类型增加方法，
但不修改原类型本身。
```

---

## 6. Declaration Merging 差异

TypeScript 支持 interface 合并：

```ts
interface User {
  id: string;
}

interface User {
  name: string;
}
```

最终 `User` 同时有 `id` 和 `name`。

Dart 不支持这种 declaration merging。一个 class/abstract class 的定义是明确的，不能在别处继续合并字段。

---

一句话理解：

```text
TypeScript 的 interface/type 更偏“描述类型形状”；
Dart 的 class/abstract class/typedef/extension 更偏“定义明确的名义类型、契约和扩展能力”。
```
