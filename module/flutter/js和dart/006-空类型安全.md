# Optional/Nullable vs Dart Null Safety

TypeScript 里“可选”和“可为空”是两个相关但不同的概念：

```ts
name?: string
name: string | null
name: string | undefined
```

Dart 里没有 `undefined`，核心是 Null Safety：

```dart
String name
String? name
```

可以这样映射：

| TypeScript                          | Dart                                            |
| ----------------------------------- | ----------------------------------------------- |
| `name?: string`                     | `String? name` / optional named parameter       |
| `name: string \| null`              | `String? name`                                  |
| `name: string \| undefined`         | 通常映射为 `String? name`                       |
| `name: string \| null \| undefined` | `String? name`                                  |
| required property                   | `required` named parameter / non-nullable field |
| optional property                   | nullable field / optional parameter             |
| `strictNullChecks`                  | Dart Null Safety                                |
| optional chaining `?.`              | null-aware access `?.`                          |
| nullish coalescing `??`             | null coalescing `??`                            |
| non-null assertion `!`              | null assertion `!`                              |

---

## 1. TypeScript 的 optional property

TypeScript：

```ts
type User = {
  id: string;
  nickname?: string;
};
```

`nickname?: string` 表示属性可以不存在。

它大致等价于：

```ts
nickname: string | undefined;
```

但对象层面有区别：

```ts
const a = { id: '1' }; // nickname 不存在
const b = { id: '1', nickname: undefined }; // nickname 存在，但值是 undefined
```

---

## 2. Dart 没有 `undefined`

Dart 里只有：

```dart
null
```

没有：

```dart
undefined
```

所以 TypeScript 里的“字段不存在”或“值是 undefined”，迁移到 Dart 时通常会用 `null` 表达。

Dart：

```dart
class User {
  const User({
    required this.id,
    this.nickname,
  });

  final String id;
  final String? nickname;
}
```

这里：

```dart
String? nickname
```

表示：

```text
nickname 可以是 String，也可以是 null。
```

---

## 3. Non-nullable vs Nullable

Dart Null Safety 默认非空：

```dart
String name = 'Tom';
```

这表示：

```text
name 必须是 String，不能是 null。
```

如果允许为空：

```dart
String? name;
```

这表示：

```text
name 可以是 String，也可以是 null。
```

对应 TypeScript：

```ts
let name: string | null;
```

---

## 4. required vs optional named parameter

Dart 构造函数里常见：

```dart
class Product {
  const Product({
    required this.id,
    required this.title,
    this.subtitle,
  });

  final String id;
  final String title;
  final String? subtitle;
}
```

含义：

| Dart                  | 含义            |
| --------------------- | --------------- |
| `required this.id`    | 调用方必须传    |
| `required this.title` | 调用方必须传    |
| `this.subtitle`       | 调用方可以不传  |
| `String? subtitle`    | 字段可以是 null |

调用：

```dart
const product = Product(
  id: '1',
  title: 'Cup',
);
```

这里没有传 `subtitle`，它会是 `null`。

---

## 5. 注意：optional parameter 不一定 nullable

Dart 中参数是否可选，和类型是否 nullable，是两个维度。

比如：

```dart
void greet([String name = 'Guest']) {}
```

这是可选参数，但不是 nullable，因为有默认值。

命名参数也一样：

```dart
void fetchProducts({int page = 1}) {}
```

`page` 可不传，但类型仍然是 `int`，不是 `int?`。

如果没有默认值，又不是 `required`，通常需要 nullable：

```dart
void greet({String? name}) {}
```

所以要区分：

```text
optional = 调用方可以不传
nullable = 值可以是 null
```

---

## 6. Null-aware 操作符

TypeScript：

```ts
user.nickname?.length;
user.nickname ?? 'Guest';
user.nickname!;
```

Dart：

```dart
user.nickname?.length
user.nickname ?? 'Guest'
user.nickname!
```

语义非常接近：

| 操作     | TypeScript | Dart |
| -------- | ---------- | ---- |
| 可选访问 | `?.`       | `?.` |
| 空值合并 | `??`       | `??` |
| 非空断言 | `!`        | `!`  |

Dart 还有：

```dart
name ??= 'Guest';
```

表示如果当前是 `null`，就赋默认值。

---

## 7. JSON 场景中的差异

TypeScript 接口：

```ts
type UserDto = {
  id: string;
  nickname?: string | null;
};
```

服务端可能返回：

```json
{ "id": "1" }
```

也可能返回：

```json
{ "id": "1", "nickname": null }
```

Dart model 通常都会映射成：

```dart
final String? nickname;
```

也就是说：

```text
字段缺失
字段为 null
```

在 Dart 业务模型里通常都会变成：

```dart
null
```

如果你需要区分“缺失”和“显式 null”，需要在 JSON 解析层单独处理。

---

一句话理解：

```text
TypeScript 同时有 optional、undefined、null；
Dart 没有 undefined，默认非空，
用 T? 表达 nullable，
用 required/default value 区分参数是否必须传。
```
