# TypeScript 类型系统 vs Dart 类型系统

TypeScript 是 JavaScript 的静态类型层，最终会被编译擦除成 JavaScript。

Dart 的类型系统是语言本身的一部分，Dart 代码运行和编译时都围绕这个类型系统设计。

可以这样映射：

| TypeScript               | Dart                                      |
| ------------------------ | ----------------------------------------- |
| 静态类型                 | 静态类型                                  |
| 类型擦除                 | 类型是语言核心能力                        |
| `interface`              | `abstract class` / `class`                |
| `type` alias             | `typedef`                                 |
| union type               | `sealed class` / `enum` / Freezed union   |
| literal type             | `enum` / `sealed class` / `const` value   |
| optional property        | nullable field / optional named parameter |
| `null`                   | `null`                                    |
| `undefined`              | 无直接等价                                |
| `T \| null`              | `T?`                                      |
| `T \| undefined`         | 通常用 `T?` 表达“可能没有值”              |
| `T \| null \| undefined` | `T?`                                      |
| structural typing        | nominal typing                            |
| generics                 | generics                                  |
| `any`                    | `dynamic`                                 |
| `unknown`                | `Object?`                                 |
| `never`                  | `Never`                                   |
| type guard               | `is` / pattern matching                   |
| utility types            | 手写模型 / codegen / extension            |
| mapped types             | 无直接等价                                |
| conditional types        | 无直接等价                                |

---

## 1. 类型系统地位不同

TypeScript：

```text
TypeScript 类型只存在于编译期；
运行时还是 JavaScript。
```

Dart：

```text
Dart 类型是语言本身的一部分；
分析、编译、运行时行为都和类型系统有关。
```

所以 TypeScript 更像：

```text
给 JavaScript 加类型约束
```

Dart 更像：

```text
从语言层面就是强类型应用开发语言
```

---

## 2. Structural Typing vs Nominal Typing

TypeScript 主要是结构类型：

```ts
type User = {
  id: string;
  name: string;
};

function printUser(user: User) {}
```

只要对象结构匹配，就可以传入。

Dart 主要是名义类型：

```dart
class User {
  final String id;
  final String name;

  User({
    required this.id,
    required this.name,
  });
}

void printUser(User user) {}
```

必须是 `User` 类型或其子类型。

核心差异：

```text
TypeScript 看“形状像不像”；
Dart 看“类型是不是”。
```

## 3. interface/type vs class

TypeScript 常用：

```ts
interface Product {
  id: string;
  title: string;
}

type ProductId = string;
```

Dart 常用：

```dart
class Product {
  final String id;
  final String title;

  Product({
    required this.id,
    required this.title,
  });
}
```

类型别名：

```dart
typedef ProductId = String;
```

接口抽象通常用：

```dart
abstract class ProductRepository {
  Future<List<Product>> fetchProducts();
}
```

## 4. Union Type vs sealed class

TypeScript 很擅长：

```ts
type LoadState =
  | { type: 'loading' }
  | { type: 'success'; data: Product[] }
  | { type: 'error'; message: string };
```

Dart 不能直接写这种对象 union，常用：

```dart
sealed class LoadState {}

class Loading extends LoadState {}

class Success extends LoadState {
  final List<Product> data;
  Success(this.data);
}

class Failure extends LoadState {
  final String message;
  Failure(this.message);
}
```

或者用 Freezed：

```dart
@freezed
sealed class LoadState with _$LoadState {
  const factory LoadState.loading() = Loading;
  const factory LoadState.success(List<Product> data) = Success;
  const factory LoadState.error(String message) = Failure;
}
```

## 5. Nullable 差异

TypeScript 里有两个常见的“空值/缺失值”概念：

```ts
null;
undefined;
```

Dart 里没有 `undefined`，只有：

```dart
null
```

所以映射关系更准确是：

| TypeScript               | Dart                         |
| ------------------------ | ---------------------------- |
| `null`                   | `null`                       |
| `undefined`              | 无直接等价                   |
| `T \| null`              | `T?`                         |
| `T \| undefined`         | 通常用 `T?` 表达“可能没有值” |
| `T \| null \| undefined` | `T?`                         |

TypeScript：

```ts
let name: string | null | undefined;
```

Dart：

```dart
String? name;
```

但要注意，Dart 的 `String?` 实际含义是：

```text
name 可以是 String，也可以是 null
```

它不包含 `undefined`。只是从业务语义迁移角度看，TypeScript 中很多 `undefined` 表示“值不存在”或“字段缺失”，在 Dart 中通常会用 `null` 表达。

使用方式比较接近：

```dart
name?.length
name ?? 'default'
name!
```

## 6. any vs dynamic

TypeScript：

```ts
let value: any;
```

Dart：

```dart
dynamic value;
```

二者都表示绕过静态检查。

但 Dart 更推荐尽量使用：

```dart
Object?
```

类比 TypeScript 的：

```ts
unknown;
```

映射：

| TypeScript  | Dart       |
| ----------- | ---------- |
| `any`       | `dynamic`  |
| `unknown`   | `Object?`  |
| `never`     | `Never`    |
| `void`      | `void`     |
| `null`      | `Null`     |
| `undefined` | 无直接等价 |

## 7. 泛型

TypeScript：

```ts
function identity<T>(value: T): T {
  return value;
}
```

Dart：

```dart
T identity<T>(T value) {
  return value;
}
```

泛型约束：

```ts
function printId<T extends { id: string }>(item: T) {}
```

Dart：

```dart
void printId<T extends HasId>(T item) {}
```

因为 Dart 是名义类型，通常需要明确抽象类型或基类。

---

## 8. Utility Types 差异

TypeScript 有很多内置工具类型：

```ts
Partial<T>;
Pick<T, K>;
Omit<T, K>;
Record<K, V>;
ReturnType<T>;
```

Dart 没有完全对应的类型编程能力。

Flutter/Dart 项目通常通过：

```text
拆分模型
copyWith
Freezed
代码生成
extension
```

来解决类似问题。

一句话理解：

```text
TypeScript 是结构化、类型擦除、类型编程能力很强的 JavaScript 类型层；
Dart 是名义化、空安全、语言原生的强类型系统，更强调明确模型和代码生成。
```
