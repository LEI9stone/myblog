# Custom Hook vs Provider / Notifier / Controller

React 里的 Custom Hook 用来复用状态逻辑、副作用逻辑和业务逻辑。

Flutter 没有内置 Hook 心智，常见对应是：

```dart
Provider
Notifier
Controller
Repository
Service
```

如果项目使用 Riverpod，那么最接近 Custom Hook 复用逻辑的通常是：

```dart
Provider / Notifier / AsyncNotifier
```

可以这样映射：

| React Custom Hook       | Flutter / Riverpod                     |
| ----------------------- | -------------------------------------- |
| `useSomething()`        | `somethingProvider`                    |
| `useState` inside hook  | `Notifier` state                       |
| `useEffect` inside hook | provider lifecycle / `ref.onDispose`   |
| return state + actions  | Notifier state + methods               |
| data fetching hook      | `FutureProvider` / `AsyncNotifier`     |
| derived hook            | computed Provider                      |
| local controller hook   | Controller object                      |
| `useRef`                | controller / `FocusNode` / `GlobalKey` |
| hook cleanup            | `dispose` / `ref.onDispose`            |

---

## 1. React Custom Hook

React：

```tsx
function useProducts() {
  const [products, setProducts] = useState<Product[]>([]);
  const [loading, setLoading] = useState(false);

  async function refresh() {
    setLoading(true);
    const data = await fetchProducts();
    setProducts(data);
    setLoading(false);
  }

  useEffect(() => {
    refresh();
  }, []);

  return {
    products,
    loading,
    refresh,
  };
}
```

使用：

```tsx
const { products, loading, refresh } = useProducts();
```

核心是：

```text
把组件里的状态逻辑抽出去复用。
```

## 2. Riverpod Provider

Flutter + Riverpod 中通常写成 provider：

```dart
final productsProvider = FutureProvider<List<Product>>((ref) async {
  final repository = ref.watch(productRepositoryProvider);
  return repository.fetchProducts();
});
```

使用：

```dart
final products = ref.watch(productsProvider);
```

UI：

```dart
switch (products) {
  case AsyncLoading():
    return const LoadingView();
  case AsyncError(:final error):
    return ErrorView(error: error);
  case AsyncData(:final value):
    return ProductList(products: value);
}
```

心智映射：

```text
useProducts()
≈ ref.watch(productsProvider)
```

## 3. Notifier：状态 + 操作

如果 Hook 返回 state 和 actions：

```tsx
const { keyword, setKeyword, submit } = useSearch();
```

Riverpod 更像：

```dart
final searchProvider =
    NotifierProvider<SearchNotifier, SearchState>(SearchNotifier.new);
```

```dart
class SearchNotifier extends Notifier<SearchState> {
  @override
  SearchState build() {
    return const SearchState(keyword: '');
  }

  void setKeyword(String value) {
    state = state.copyWith(keyword: value);
  }

  Future<void> submit() async {
    // ...
  }
}
```

使用：

```dart
final state = ref.watch(searchProvider);
final notifier = ref.read(searchProvider.notifier);

notifier.setKeyword('cup');
```

对应关系：

```text
Hook return state
≈ provider state

Hook return actions
≈ notifier methods
```

## 4. AsyncNotifier：异步业务状态

React：

```tsx
const { data, loading, error, refresh } = useProductList();
```

Riverpod：

```dart
final productListProvider =
    AsyncNotifierProvider<ProductListNotifier, List<Product>>(
  ProductListNotifier.new,
);
```

```dart
class ProductListNotifier extends AsyncNotifier<List<Product>> {
  @override
  Future<List<Product>> build() async {
    final repository = ref.watch(productRepositoryProvider);
    return repository.fetchProducts();
  }

  Future<void> refresh() async {
    state = const AsyncLoading();
    state = await AsyncValue.guard(() async {
      final repository = ref.read(productRepositoryProvider);
      return repository.fetchProducts();
    });
  }
}
```

UI：

```dart
final products = ref.watch(productListProvider);
```

## 5. Controller

React Hook 常用于封装局部 controller：

```tsx
function useSearchInput() {
  const [value, setValue] = useState('');
  const inputRef = useRef<HTMLInputElement>(null);

  return { value, setValue, inputRef };
}
```

Flutter 中常用 Controller：

```dart
late final TextEditingController searchController;
late final FocusNode searchFocusNode;
```

在 `StatefulWidget` 里：

```dart
@override
void initState() {
  super.initState();
  searchController = TextEditingController();
  searchFocusNode = FocusNode();
}

@override
void dispose() {
  searchController.dispose();
  searchFocusNode.dispose();
  super.dispose();
}
```

如果想复用更复杂交互，也可以封装成一个 controller class：

```dart
class SearchController {
  SearchController() : textController = TextEditingController();

  final TextEditingController textController;

  void dispose() {
    textController.dispose();
  }
}
```

## 6. Provider vs Controller 怎么分

| 场景               | 推荐                               |
| ------------------ | ---------------------------------- |
| 跨组件共享业务状态 | Provider / Notifier                |
| 异步数据请求状态   | FutureProvider / AsyncNotifier     |
| 派生状态           | Provider                           |
| 表单输入控制       | TextEditingController / Form state |
| 动画控制           | AnimationController                |
| 页面滚动控制       | ScrollController                   |
| 焦点控制           | FocusNode                          |
| 业务数据访问       | Repository                         |
| 复杂页面协调       | Page Controller / Notifier 组合    |

简单理解：

```text
Provider/Notifier 管业务状态；
Controller 管某个 UI/交互对象的命令式控制；
Repository 管数据来源。
```

## 7. 生命周期清理

React Hook：

```tsx
useEffect(() => {
  return () => cleanup();
}, []);
```

Flutter Controller：

```dart
@override
void dispose() {
  controller.dispose();
  super.dispose();
}
```

Riverpod：

```dart
final provider = Provider((ref) {
  final controller = TextEditingController();

  ref.onDispose(controller.dispose);

  return controller;
});
```

---

一句话理解：

```text
React Custom Hook 用函数复用状态和副作用逻辑；
Flutter 通常用 Provider/Notifier 复用业务状态，
用 Controller 复用和管理 UI 控制对象，
用 Repository 封装数据访问。
```
