# Storybook vs Widget Preview / Golden Test

Web 里 Storybook 用来独立预览、调试和文档化组件。

Flutter 中没有官方完全等价的内置 Storybook，但常见替代是：

```text
Widgetbook
自建 preview page
Widget tests
Golden tests
```

可以这样映射：

| Web Storybook          | Flutter                          |
| ---------------------- | -------------------------------- |
| Storybook              | Widgetbook / Preview App         |
| Story                  | Use case / Preview case          |
| Controls               | Knobs / Addons / 自定义参数面板  |
| Visual regression      | Golden test                      |
| Component docs         | Widget preview docs              |
| Interaction test       | Widget test                      |
| Screenshot test        | Golden test                      |
| Design system showcase | Widgetbook / Showcase page       |
| Chromatic              | Golden test CI / screenshot diff |

---

## 1. Storybook 的作用

Web 中 Storybook 常用于：

```text
独立开发组件
展示组件不同状态
测试交互
沉淀设计系统文档
做视觉回归
```

例如：

```text
Button/default
Button/loading
Button/disabled
ProductCard/normal
ProductCard/soldOut
EmptyState/noData
```

---

## 2. Flutter Widget Preview

Flutter 常见做法是做一个 preview page：

```dart
class WidgetPreviewPage extends StatelessWidget {
  const WidgetPreviewPage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: ListView(
        padding: const EdgeInsets.all(16),
        children: const [
          EmptyState(title: '暂无数据'),
          SizedBox(height: 24),
          ErrorView(message: '加载失败'),
          SizedBox(height: 24),
          ProductCardPreview(),
        ],
      ),
    );
  }
}
```

适合：

```text
项目内部快速查看共享组件
开发时人工检查 UI
沉淀组件状态样例
```

---

## 3. Widgetbook

Flutter 生态里更接近 Storybook 的是：

```text
Widgetbook
```

它可以组织组件 use case，并在应用里预览不同状态。

概念映射：

```text
Storybook Story
≈ Widgetbook Use Case
```

适合：

```text
设计系统较多
组件状态复杂
团队需要统一组件展示入口
需要类似 Storybook 的开发体验
```

---

## 4. Widget Test

Storybook 偏预览，Flutter 的 Widget Test 偏行为和结构验证。

示例：

```dart
testWidgets('shows empty state title', (tester) async {
  await tester.pumpWidget(
    const MaterialApp(
      home: EmptyState(title: '暂无数据'),
    ),
  );

  expect(find.text('暂无数据'), findsOneWidget);
});
```

适合检查：

```text
文本是否出现
点击是否触发
loading/error/data 状态切换
输入交互
列表渲染数量
```

---

## 5. Golden Test

Golden Test 用来做视觉快照测试。

心智类似：

```text
截图基准图
之后测试时重新截图
对比是否发生视觉变化
```

适合：

```text
设计系统组件
卡片
空状态
错误状态
复杂布局
主题切换
多屏尺寸
```

简单概念：

```dart
await expectLater(
  find.byType(ProductCard),
  matchesGoldenFile('goldens/product_card.png'),
);
```

实际项目通常会配合：

```text
golden_toolkit
固定字体
固定窗口尺寸
CI 截图对比
```

---

## 6. 怎么选

| 需求             | Flutter 推荐              |
| ---------------- | ------------------------- |
| 人工浏览组件状态 | Preview Page / Widgetbook |
| 团队组件展示系统 | Widgetbook                |
| 验证交互行为     | Widget Test               |
| 验证视觉不变     | Golden Test               |
| 防止 UI 回归     | Golden Test + CI          |
| 快速开发单个组件 | Preview Page              |
| 设计系统文档化   | Widgetbook                |

---

## 7. 推荐落地顺序

对多数 Flutter 项目来说，可以渐进：

```text
先写 Widget Test 覆盖关键行为
再为核心组件做 Preview Page
组件体系变大后引入 Widgetbook
重要视觉组件再补 Golden Test
```

不要一开始就强行搭一套很重的组件文档系统，除非项目明确有设计系统维护需求。

---

一句话理解：

```text
Storybook 是 Web 组件的独立预览和文档系统；
Flutter 里可以用 Widgetbook 或自建 Preview Page 做组件预览，
用 Widget Test 验证行为，
用 Golden Test 做视觉回归。
```
