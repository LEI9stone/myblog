# Deep Link vs App Link / Universal Link

Web 里的 Deep Link 指用户可以直接通过 URL 进入某个具体页面：

```text
https://example.com/products/123
```

Flutter App 里也可以支持类似能力，但移动端需要通过平台机制把外部链接交给 App 处理：

```text
Android App Links
iOS Universal Links
Custom Scheme
```

可以这样映射：

| Web Deep Link         | Flutter / Mobile          |
| --------------------- | ------------------------- |
| URL 直达页面          | Deep Link 直达 App 页面   |
| `/products/123`       | app route `/products/123` |
| Browser 打开 URL      | 系统唤起 App              |
| React Router 解析 URL | go_router 解析 route      |
| query params          | route query parameters    |
| path params           | route path parameters     |
| `https://...`         | App Link / Universal Link |
| `myapp://...`         | Custom URL Scheme         |
| fallback web page     | 未安装 App 时打开网页     |

---

## 1. Web Deep Link

Web：

```text
https://shop.example.com/products/123?tab=reviews
```

用户可以：

```text
从搜索结果打开
从聊天链接打开
刷新页面
收藏链接
复制分享
```

前端 Router 根据 URL 渲染对应页面。

React Router：

```tsx
<Route path="/products/:id" element={<ProductDetailPage />} />
```

---

## 2. Flutter Deep Link

Flutter App 也可以接收外部链接：

```text
https://shop.example.com/products/123
```

或者：

```text
rouzao://products/123
```

App 被唤起后，路由系统把链接解析成页面：

```dart
GoRoute(
  path: '/products/:id',
  builder: (context, state) {
    final id = state.pathParameters['id']!;
    return ProductDetailPage(productId: id);
  },
)
```

核心心智：

```text
外部链接 → 系统交给 App → Flutter Router 解析 → 打开对应页面
```

---

## 3. App Link / Universal Link

移动端推荐使用 HTTPS 链接：

```text
https://shop.example.com/products/123
```

对应平台能力：

| 平台    | 名称            |
| ------- | --------------- |
| Android | App Links       |
| iOS     | Universal Links |

优点：

```text
链接看起来像普通网页 URL；
安装 App 时可以打开 App；
没安装 App 时可以打开网页；
比 custom scheme 更可靠。
```

---

## 4. Custom URL Scheme

也可以使用自定义协议：

```text
rouzao://products/123
```

优点：

```text
配置相对简单
适合内部跳转、第三方回调
```

缺点：

```text
没安装 App 时体验差
不同 App 可能抢同一个 scheme
不如 HTTPS 链接通用
```

所以常见建议是：

```text
对外分享链接：App Link / Universal Link
内部或第三方回调：Custom Scheme
```

---

## 5. go_router 中的 Deep Link 心智

如果 Flutter 使用 `go_router`，Deep Link 最终会进入已有路由表：

```dart
GoRoute(
  path: '/orders/:orderId',
  builder: (context, state) {
    final orderId = state.pathParameters['orderId']!;
    return OrderDetailPage(orderId: orderId);
  },
)
```

链接：

```text
https://shop.example.com/orders/1001
```

进入 App 后对应：

```text
/orders/1001
```

然后打开：

```text
OrderDetailPage(orderId: '1001')
```

---

## 6. 登录态处理

Deep Link 经常遇到：

```text
用户点订单详情链接
但当前未登录
```

常见流程：

```text
打开 deep link
检查登录态
未登录跳登录页，并保存目标地址
登录成功后回到原 deep link 页面
```

类似 Web：

```text
/login?redirect=/orders/1001
```

Flutter 里也可以：

```dart
/login?redirect=/orders/1001
```

配合 `go_router redirect` 做 Auth Guard。

---

## 7. 冷启动 vs 热启动

Web Deep Link 通常是浏览器打开 URL。

Flutter App Deep Link 要考虑两种情况：

| 场景   | 含义                             |
| ------ | -------------------------------- |
| 冷启动 | App 没运行，链接启动 App         |
| 热启动 | App 已在后台或前台，链接切到 App |

两种情况都应该能正确进入目标 route。

---

一句话理解：

```text
Web Deep Link 是 URL 直接进入网页某个页面；
Flutter Deep Link 是外部链接唤起 App 后进入某个 Route。
Android 用 App Links，
iOS 用 Universal Links，
Flutter 侧通常交给 go_router/Navigator 解析到具体页面。
```
