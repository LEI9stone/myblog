# Web Storage Security vs Mobile Secure Storage

Web Storage Security 主要关注：

```text
localStorage/sessionStorage 是否会被 XSS 读取
Cookie 是否 HttpOnly/Secure/SameSite
浏览器同源策略
CSRF 风险
```

Mobile Secure Storage 主要关注：

```text
token 是否存入系统安全存储
设备丢失/越狱/root 风险
日志泄露
备份策略
生物识别/Keychain/Keystore
```

可以这样映射：

| Web Storage     | Flutter / Mobile                              |
| --------------- | --------------------------------------------- |
| localStorage    | shared_preferences，不适合敏感信息            |
| sessionStorage  | runtime memory state                          |
| HttpOnly Cookie | 无完全等价                                    |
| Secure Cookie   | HTTPS + secure token storage                  |
| IndexedDB       | drift/sqlite，不适合裸存敏感 token            |
| memory token    | Provider/AuthState memory                     |
| Web Crypto      | platform crypto / secure enclave capabilities |
| secure storage  | `flutter_secure_storage`                      |
| browser sandbox | app sandbox + OS security                     |

---

## 1. Web 存储安全

Web 中常见风险：

```text
localStorage token 被 XSS 读取
sessionStorage token 被 JS 读取
Cookie 自动发送导致 CSRF
非 Secure Cookie 被明文传输
敏感信息进入 IndexedDB
浏览器插件或调试工具暴露数据
```

所以 Web 常推荐：

```text
HttpOnly + Secure + SameSite Cookie
严格 CSP
避免把敏感 token 放 localStorage
```

---

## 2. Flutter 本地存储安全

Flutter 中常见存储：

| 存储                     | 适合             |
| ------------------------ | ---------------- |
| `shared_preferences`     | 非敏感配置       |
| `flutter_secure_storage` | token/敏感小数据 |
| `drift/sqlite`           | 结构化业务数据   |
| 文件系统                 | 图片/文件缓存    |
| memory state             | 运行期临时数据   |

认证 token 推荐：

```text
flutter_secure_storage
```

非敏感配置才用：

```text
shared_preferences
```

---

## 3. flutter_secure_storage

`flutter_secure_storage` 通常基于平台安全能力：

```text
iOS Keychain
Android Keystore / encrypted storage
```

它比普通 key-value 存储更适合保存：

```text
access token
refresh token
设备级凭证
小体积敏感配置
```

但它也不是“绝对安全”：

```text
root/越狱设备风险更高
运行时内存仍可能被调试
日志泄露仍然危险
后端 token 策略仍然重要
```

---

## 4. HttpOnly Cookie 的差异

Web 的 HttpOnly Cookie：

```text
JS 不能读取 token；
浏览器自动随请求发送。
```

Flutter secure storage：

```text
App 代码可以读取 token；
然后放到 Authorization header。
```

所以它不是 HttpOnly Cookie 的等价替代。

Flutter 要靠：

```text
secure storage
HTTPS
token 短有效期
refresh token 轮换
登出清理
避免日志输出
必要时设备完整性检测
```

降低风险。

---

## 5. 不要把敏感信息放普通存储

不推荐：

```dart
await prefs.setString('access_token', token);
```

推荐：

```dart
await secureStorage.write(
  key: 'access_token',
  value: token,
);
```

也不要把 token 打进日志：

```dart
debugPrint('token: $token'); // 不推荐
```

Dio log interceptor 也要避免打印：

```text
Authorization header
refresh token
password
payment data
```

---

## 6. 数据库中的敏感数据

drift/sqlite 适合结构化数据，但默认不是专门的安全存储。

如果需要存敏感业务数据，要考虑：

```text
是否必须离线保存
是否需要加密数据库
是否可以只保存脱敏数据
是否可以服务端按需获取
用户登出时是否清理
```

---

## 7. 推荐分层

| 数据                         | 推荐存储                   |
| ---------------------------- | -------------------------- |
| 主题、语言、引导状态         | `shared_preferences`       |
| access token / refresh token | `flutter_secure_storage`   |
| 当前用户内存状态             | Provider/AuthState         |
| 商品/订单离线缓存            | drift/sqlite               |
| 搜索历史                     | shared_preferences / drift |
| 图片缓存                     | cached_network_image       |
| 密码/支付密钥                | 尽量不落客户端             |

一句话理解：

```text
Web 存储安全重点是 XSS、Cookie 属性、同源和 CSRF；
Flutter 移动端重点是把敏感 token 放到 secure storage，
避免日志泄露，
用 HTTPS 和合理 token 生命周期配合后端安全策略。
shared_preferences/local database 不应裸存敏感凭证。
```
