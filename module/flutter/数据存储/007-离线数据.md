# Offline Data vs Local Database

Web 里的 Offline Data 通常依赖：

```text
Service Worker
Cache Storage
IndexedDB
localStorage
PWA
```

Flutter 里的离线数据通常依赖：

```text
Local Database
Repository Cache
Sync Queue
Connectivity Handling
```

其中结构化离线数据最常用的是：

```text
SQLite / drift
```

可以这样映射：

| Web Offline Data     | Flutter                                      |
| -------------------- | -------------------------------------------- |
| IndexedDB            | drift / SQLite                               |
| Service Worker Cache | Repository cache / file cache                |
| Cache Storage        | local database / local files                 |
| PWA offline          | App offline mode                             |
| sync queue           | local pending operation table                |
| optimistic update    | local update + background sync               |
| network status       | connectivity_plus / request failure handling |
| stale data           | cached local data                            |
| revalidate           | background refresh                           |
| conflict resolution  | sync strategy                                |

---

## 1. Web Offline Data

Web PWA 常见模式：

```text
缓存静态资源
缓存接口响应
IndexedDB 存结构化数据
离线时展示本地数据
联网后同步
```

适合：

```text
离线可读
草稿保存
待同步操作
弱网体验
```

---

## 2. Flutter Local Database

Flutter App 中离线数据更常见：

```text
SQLite 数据库
本地文件
shared_preferences
secure storage
```

结构化数据推荐：

```text
drift / sqlite
```

例如：

```text
商品表
订单草稿表
搜索历史表
待同步操作表
```

---

## 3. Repository 负责离线策略

推荐数据流：

```text
UI
→ Provider/Notifier
→ Repository
→ Local Database + Remote API
```

Repository 决定：

```text
离线时读本地
在线时拉远程
远程成功后写本地
提交失败时写同步队列
后台或下次启动再同步
```

UI 不应该直接关心“现在读的是本地还是网络”。

---

## 4. 只读离线缓存

适合商品、分类、配置等数据：

```text
先展示本地缓存
再请求远程刷新
刷新成功后更新本地
```

流程：

```text
read local products
emit cached products
fetch remote products
save remote products to local db
emit updated products
```

如果用 drift 的 `watch`：

```text
UI 监听本地数据库 stream；
Repository 刷新远程数据并写库；
UI 自动更新。
```

---

## 5. 可写离线数据

例如用户离线提交表单：

```text
用户提交
写入本地 pending queue
UI 显示“待同步”
联网后后台同步
成功后标记已同步
失败后保留错误状态
```

本地表可能包含：

```text
operation_id
type
payload
status
created_at
retry_count
last_error
```

这比简单缓存复杂，需要明确业务策略。

---

## 6. 冲突处理

离线可写数据要考虑：

```text
本地改了，服务端也改了怎么办
重复提交怎么办
同步顺序怎么保证
失败重试几次
用户是否能手动重试
```

常见策略：

```text
服务端为准
客户端为准
按更新时间合并
人工解决冲突
操作日志顺序同步
```

---

## 7. 什么时候需要 Local Database

适合：

```text
大量结构化数据
需要离线访问
需要复杂查询
需要排序筛选
需要同步队列
App 重启后仍保留
多表关系
```

不需要数据库的场景：

```text
主题模式
语言偏好
是否看过引导页
少量缓存 key-value
token
```

这些分别用：

```text
shared_preferences
flutter_secure_storage
```

---

一句话理解：

```text
Web Offline Data 常依赖 Service Worker、Cache Storage 和 IndexedDB；
Flutter Offline Data 通常由 Repository + Local Database 实现。
结构化离线数据用 drift/sqlite，
Repository 负责缓存、刷新、同步队列和冲突策略，
UI 只消费最终状态。
```
