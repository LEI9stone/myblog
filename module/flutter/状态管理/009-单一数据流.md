# State Mutation vs Immutable State

Web 状态管理里经常强调：

```text
不要直接 mutate state；
用 immutable update 生成新 state。
```

Flutter / Riverpod 中同样推荐使用不可变状态，尤其是业务状态、列表状态和异步状态。

可以这样映射：

| Web                            | Flutter / Dart                              |
| ------------------------------ | ------------------------------------------- |
| mutable state                  | mutable object / mutable List               |
| immutable state                | `final` fields + copyWith                   |
| Redux reducer immutable update | Notifier 中赋新 state                       |
| Zustand set new object         | `state = state.copyWith(...)`               |
| Immer                          | Freezed / copyWith                          |
| object spread                  | `copyWith`                                  |
| array spread                   | `[...items, newItem]`                       |
| direct mutation bug            | 原地改对象但 UI 不更新                      |
| shallow equality               | provider state comparison / rebuild trigger |

---

## 1. Web 中的 Mutation 问题

React 中不推荐：

```tsx
items.push(newItem);
setItems(items);
```

推荐：

```tsx
setItems([...items, newItem]);
```

原因是：

```text
直接修改旧对象，框架可能无法识别状态变化；
也容易引入不可预测副作用。
```

---

## 2. Flutter 中同样要避免原地改业务状态

Riverpod Notifier 中不推荐：

```dart
state.items.add(product);
state = state;
```

推荐：

```dart
state = state.copyWith(
  items: [...state.items, product],
);
```

或者如果 state 本身是 List：

```dart
state = [...state, product];
```

核心是：

```text
创建新的 state 对象，而不是原地修改旧对象。
```

---

## 3. Immutable State Model

Dart 中常见不可变状态：

```dart
class CartState {
  const CartState({
    required this.items,
    required this.total,
  });

  final List<CartItem> items;
  final Decimal total;

  CartState copyWith({
    List<CartItem>? items,
    Decimal? total,
  }) {
    return CartState(
      items: items ?? this.items,
      total: total ?? this.total,
    );
  }
}
```

更新：

```dart
state = state.copyWith(
  items: [...state.items, newItem],
);
```

---

## 4. Freezed

复杂状态常用 Freezed：

```dart
@freezed
abstract class CartState with _$CartState {
  const factory CartState({
    required List<CartItem> items,
    required Decimal total,
  }) = _CartState;
}
```

使用：

```dart
state = state.copyWith(
  items: [...state.items, newItem],
);
```

它类似 Web 里的：

```text
类型安全的 immutable model + copyWith
```

某种程度上承担了部分 Immer/utility type 的角色。

---

## 5. List 的坑

Dart 的 `final` 不等于 List 内容不可变：

```dart
final items = <Product>[];
items.add(product); // 允许
```

`final` 只是表示变量不能重新赋值：

```dart
items = []; // 不允许
```

但 List 内部仍然可变。

所以不可变状态中要避免暴露可变 List 被外部修改。常见做法：

```dart
List.unmodifiable(items)
```

或使用 Freezed 的不可变集合配置。

---

## 6. StatefulWidget local state 可以适度 mutable

局部 UI 状态中，简单可变字段是正常的：

```dart
var expanded = false;

setState(() {
  expanded = !expanded;
});
```

这没问题，因为它只属于当前 State 对象。

但业务状态、Provider state、跨组件共享状态更推荐 immutable。

区分：

| 状态           | 推荐                           |
| -------------- | ------------------------------ |
| 局部 bool/int  | 可直接 mutable + setState      |
| Controller     | mutable object                 |
| 业务 State     | immutable                      |
| 列表数据       | immutable update               |
| 服务端数据模型 | immutable model                |
| 表单草稿       | 可局部 mutable，提交时转 model |

---

## 7. 为什么 Flutter/Riverpod 推荐 immutable

好处：

```text
状态变化更清晰
容易触发 rebuild
避免引用共享导致的隐藏修改
更容易测试
更适合 undo/redo、缓存、日志
和 Freezed/json_serializable 配合好
```

---

一句话理解：

```text
Web 里 React/Redux/Zustand 通常避免直接 mutate state；
Flutter/Riverpod 也一样：
局部 UI 状态可以用 setState 修改字段，
但业务状态和 Provider state 推荐不可变对象，
通过 copyWith、展开 List、Freezed 生成新 state。
```
