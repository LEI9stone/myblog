# Side Effects vs Notifier / Controller / Effect Layer

Web 里 Side Effects 通常指渲染之外的副作用，比如请求接口、写缓存、订阅事件、操作 DOM、埋点、定时器。

React 中常见副作用入口是：

```tsx
useEffect
event handler
custom hook
middleware
```

Flutter 中没有完全对应的统一 `useEffect`，通常按职责放到：

```dart
Notifier
Controller
Repository
Widget lifecycle
Provider lifecycle
Effect layer
```

可以这样映射：

| Web Side Effect       | Flutter                                    |
| --------------------- | ------------------------------------------ |
| `useEffect` fetch     | `FutureProvider` / `AsyncNotifier.build()` |
| event handler effect  | button callback / Notifier method          |
| custom hook effect    | Provider / Notifier / Controller           |
| Redux thunk/saga      | Notifier / Repository / use case           |
| DOM effect            | Widget lifecycle / Controller              |
| subscription cleanup  | `dispose()` / `ref.onDispose`              |
| timer                 | `Timer` + dispose / provider cleanup       |
| localStorage write    | storage repository / preferences provider  |
| analytics             | effect service / Notifier method           |
| imperative UI control | Controller                                 |

---

## 1. Web Side Effects

React：

```tsx
useEffect(() => {
  fetchProducts();
}, []);
```

或者：

```tsx
useEffect(() => {
  const timer = setInterval(...)
  return () => clearInterval(timer)
}, [])
```

副作用特点：

```text
不是纯 UI 计算；
会影响外部世界；
需要生命周期和清理。
```

---

## 2. 数据请求：FutureProvider / AsyncNotifier

React：

```tsx
useEffect(() => {
  fetchProducts().then(setProducts);
}, []);
```

Riverpod：

```dart
final productsProvider = FutureProvider<List<Product>>((ref) async {
  final repository = ref.watch(productRepositoryProvider);
  return repository.fetchProducts();
});
```

如果需要刷新、分页、提交等操作：

```dart
class ProductListNotifier extends AsyncNotifier<List<Product>> {
  @override
  Future<List<Product>> build() async {
    final repository = ref.watch(productRepositoryProvider);
    return repository.fetchProducts();
  }

  Future<void> refresh() async {
    state = const AsyncLoading();
    state = await AsyncValue.guard(() {
      return ref.read(productRepositoryProvider).fetchProducts();
    });
  }
}
```

## 3. 用户操作副作用：Notifier method

Web：

```tsx
async function handleSubmit() {
  await api.submit(form);
  toast.success('Saved');
}
```

Flutter：

```dart
class SubmitNotifier extends AsyncNotifier<void> {
  @override
  Future<void> build() async {}

  Future<void> submit(FormData data) async {
    state = const AsyncLoading();

    state = await AsyncValue.guard(() async {
      await ref.read(repositoryProvider).submit(data);
    });
  }
}
```

UI 里触发：

```dart
ref.read(submitProvider.notifier).submit(data);
```

UI 只负责响应状态：

```text
loading
success
error
```

## 4. Controller 负责命令式副作用

Flutter 中很多对象本身就是 effectful controller：

```text
TextEditingController
ScrollController
AnimationController
PageController
TabController
FocusNode
VideoPlayerController
```

它们需要创建和释放：

```dart
late final ScrollController scrollController;

@override
void initState() {
  super.initState();
  scrollController = ScrollController();
}

@override
void dispose() {
  scrollController.dispose();
  super.dispose();
}
```

对应 React：

```tsx
useRef
useEffect cleanup
imperative handle
```

## 5. Provider lifecycle cleanup

React：

```tsx
useEffect(() => {
  const sub = subscribe();
  return () => sub.unsubscribe();
}, []);
```

Riverpod：

```dart
final streamProvider = Provider((ref) {
  final subscription = subscribe();

  ref.onDispose(() {
    subscription.cancel();
  });

  return subscription;
});
```

`ref.onDispose` 对应：

```text
effect cleanup
```

---

## 6. Repository 放数据副作用

网络、本地存储、数据库读写不建议散落在 Widget 中。

推荐：

```dart
class ProductRepository {
  Future<List<Product>> fetchProducts() async {
    return remoteDataSource.fetchProducts();
  }

  Future<void> cacheProducts(List<Product> products) async {
    return localDataSource.saveProducts(products);
  }
}
```

Provider/Notifier 调用 repository，UI 不直接关心数据来源。

---

## 7. UI Side Effect

有些副作用是纯 UI 层的，例如：

```text
弹 toast/snackbar
打开 dialog
跳转页面
滚动到顶部
请求焦点
播放动画
```

这些通常放在：

```text
button callback
ref.listen
post frame callback
controller method
```

例如监听提交成功后弹提示：

```dart
ref.listen(submitProvider, (previous, next) {
  if (next is AsyncData) {
    ScaffoldMessenger.of(context).showSnackBar(
      const SnackBar(content: Text('保存成功')),
    );
  }
});
```

---

## 8. 怎么分层

| 副作用类型         | 推荐位置                                       |
| ------------------ | ---------------------------------------------- |
| 网络请求           | Repository + FutureProvider/AsyncNotifier      |
| 数据缓存           | Repository / Storage service                   |
| 表单提交           | Notifier method                                |
| 埋点               | Analytics service / Notifier method / UI event |
| 定时器             | State/Provider lifecycle + cleanup             |
| 控制滚动/动画/焦点 | Controller                                     |
| 弹窗/Toast/导航    | UI layer / listener                            |
| 订阅流             | StreamProvider / ref.onDispose                 |

一句话理解：

```text
React 常用 useEffect 承载副作用；
Flutter 更倾向按职责拆分：
数据副作用放 Repository/Provider，
业务副作用放 Notifier，
命令式 UI 控制放 Controller，
生命周期清理由 dispose 或 ref.onDispose 处理。
```
