# Cache State vs Repository / Provider Cache

Web 里的 Cache State 通常指缓存服务端数据或计算结果，比如 React Query cache、SWR cache、Redux store cache、浏览器 storage cache。

Flutter 中常见缓存分两层：

```text
Provider Cache：内存中的状态缓存
Repository Cache：数据层缓存，可来自内存、本地数据库、文件或接口策略
```

可以这样映射：

| Web Cache State      | Flutter / Riverpod                            |
| -------------------- | --------------------------------------------- |
| React Query cache    | Provider cache / AsyncValue                   |
| SWR cache            | FutureProvider / AsyncNotifier + invalidation |
| Redux cached data    | Notifier state                                |
| Zustand cached state | Provider state                                |
| localStorage cache   | shared_preferences                            |
| IndexedDB cache      | drift / sqlite                                |
| memory cache         | Repository 内存缓存                           |
| query key cache      | provider.family 参数缓存                      |
| invalidate query     | `ref.invalidate(provider)`                    |
| refetch              | `ref.refresh(provider)` / notifier method     |

---

## 1. Web Cache State

Web 里常见：

```ts
useQuery(['products'], fetchProducts);
```

React Query 会缓存：

```text
data
loading
error
stale 状态
请求时间
query key
```

组件再次进入时，可以复用缓存数据，而不是立刻重新请求。

---

## 2. Riverpod Provider Cache

Riverpod 的 provider 本身会缓存计算结果。

例如：

```dart
final productsProvider = FutureProvider<List<Product>>((ref) async {
  final repository = ref.watch(productRepositoryProvider);
  return repository.fetchProducts();
});
```

当 UI 读取：

```dart
final products = ref.watch(productsProvider);
```

Riverpod 会缓存这个 provider 的结果。

再次读取同一个 provider 时，不一定重新请求，取决于 provider 生命周期和是否被销毁。

---

## 3. provider.family 类似 query key

Web：

```ts
useQuery(['product', productId], () => fetchProduct(productId));
```

Riverpod：

```dart
final productProvider =
    FutureProvider.family<Product, String>((ref, productId) async {
  final repository = ref.watch(productRepositoryProvider);
  return repository.fetchProduct(productId);
});
```

使用：

```dart
final product = ref.watch(productProvider(productId));
```

这里：

```text
productProvider(productId)
≈ query key ['product', productId]
```

不同参数会有不同缓存实例。

---

## 4. invalidate / refresh

React Query：

```ts
queryClient.invalidateQueries(['products']);
```

Riverpod：

```dart
ref.invalidate(productsProvider);
```

强制刷新并获取新值：

```dart
ref.refresh(productsProvider);
```

如果是 family：

```dart
ref.invalidate(productProvider(productId));
```

---

## 5. Repository Cache

Provider cache 是状态层缓存，Repository cache 是数据层缓存。

Repository 可以缓存：

```text
接口返回数据
分页结果
详情数据
本地数据库结果
图片 URL 映射
配置数据
```

示例：

```dart
class ProductRepository {
  List<Product>? _cachedProducts;

  Future<List<Product>> fetchProducts() async {
    if (_cachedProducts != null) {
      return _cachedProducts!;
    }

    final products = await remote.fetchProducts();
    _cachedProducts = products;
    return products;
  }
}
```

更复杂时可能用：

```text
drift
shared_preferences
flutter_secure_storage
文件缓存
内存 Map
```

---

## 6. Provider Cache vs Repository Cache 怎么分

| 类型                   | 适合放哪里              |
| ---------------------- | ----------------------- |
| 当前页面异步状态       | Provider cache          |
| loading/error/data     | AsyncValue              |
| 请求参数对应结果       | provider.family         |
| 跨 provider 共享数据源 | Repository cache        |
| 离线数据               | Repository + drift      |
| 用户偏好               | shared_preferences      |
| token                  | flutter_secure_storage  |
| 需要持久化的缓存       | Repository / Storage 层 |
| 临时内存缓存           | Provider 或 Repository  |

简单理解：

```text
Provider cache 管 UI 状态生命周期；
Repository cache 管数据来源和复用策略。
```

---

## 7. autoDispose 与缓存生命周期

Riverpod 中如果使用：

```dart
FutureProvider.autoDispose
```

当没有监听者时，provider 可能被销毁，缓存也会释放。

如果希望保留一段缓存，可以使用：

```dart
ref.keepAlive();
```

或者把缓存放到 Repository 层，让数据不跟随 UI 生命周期销毁。

---

## 8. 不要把缓存逻辑散落在 UI 里

不推荐：

```dart
if (cachedProducts != null) {
  return ProductList(cachedProducts);
}
```

更推荐：

```text
UI 只消费 provider state；
provider 或 repository 决定从缓存、本地库还是网络取数据。
```

这样 UI 只关心：

```text
loading
error
data
empty
refresh
```

---

一句话理解：

```text
Web Cache State 常由 React Query/SWR/Store 管理；
Flutter 中 Provider cache 负责缓存状态和异步结果，
Repository cache 负责数据层缓存和持久化策略。
简单请求靠 FutureProvider 缓存，
复杂缓存策略放到 Repository。
```
