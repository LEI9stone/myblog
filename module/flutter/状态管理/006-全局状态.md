# Global State vs App-level Provider

Web 里的 Global State 通常指跨页面、跨组件共享的状态，比如登录用户、购物车、主题、语言、全局配置。

Flutter + Riverpod 中通常用 App-level Provider 表达这类状态，也就是在 `ProviderScope` 下全局可访问的 provider。

可以这样映射：

| Web Global State        | Flutter / Riverpod           |
| ----------------------- | ---------------------------- |
| Redux global store      | `ProviderScope` + providers  |
| Zustand global store    | app-level provider           |
| Jotai atoms             | providers                    |
| React Context app state | Provider / Riverpod provider |
| auth state              | `authProvider`               |
| cart state              | `cartProvider`               |
| theme state             | `themeModeProvider`          |
| locale state            | `localeProvider`             |
| app config              | `appConfigProvider`          |
| global service          | repository/service provider  |

---

## 1. Web Global State

Web 中可能有：

```ts
const useAuthStore = create(...)
const useCartStore = create(...)
const ThemeContext = createContext(...)
```

这些状态可以被多个页面或组件访问。

典型全局状态：

```text
当前登录用户
认证 token
购物车
主题模式
语言
应用配置
全局消息
```

---

## 2. Riverpod App-level Provider

Flutter 中通常在 app 根部包：

```dart
ProviderScope(
  child: MyApp(),
)
```

然后定义 provider：

```dart
final authProvider =
    NotifierProvider<AuthNotifier, AuthState>(AuthNotifier.new);
```

任何 `ConsumerWidget` / `ConsumerStatefulWidget` 子树都可以读取：

```dart
final auth = ref.watch(authProvider);
```

这就相当于：

```text
App-level global state
```

---

## 3. App-level 不等于什么都放全局

全局状态应该谨慎。

适合放 app-level provider：

```text
登录态
当前用户
主题
语言
购物车
全局配置
Repository / API client
Feature 级缓存状态
```

不适合放全局：

```text
某个弹窗是否打开
某个卡片是否 hover
某个页面临时 tab index
某个输入框临时文本
一次性按钮 loading
```

这些更适合：

```text
StatefulWidget
局部 Provider
页面级 Notifier
Controller
```

---

## 4. ProviderScope 类似 Store Provider

Redux：

```tsx
<Provider store={store}>
  <App />
</Provider>
```

Riverpod：

```dart
ProviderScope(
  child: App(),
)
```

区别是：

```text
Redux 通常一个集中 store；
Riverpod 是一张 provider graph。
```

每个 provider 是一个独立状态单元或依赖单元。

---

## 5. Service / Repository 也可以是 Provider

全局不只放“状态”，也可以放依赖：

```dart
final dioProvider = Provider<Dio>((ref) {
  return Dio();
});

final productRepositoryProvider = Provider<ProductRepository>((ref) {
  final dio = ref.watch(dioProvider);
  return RemoteProductRepository(dio);
});
```

对应 Web：

```text
apiClient singleton
repository instance
dependency injection container
```

---

## 6. 页面级 Provider

如果状态只属于某个页面，可以靠作用域限制：

```dart
ProviderScope(
  overrides: [
    // page-specific overrides
  ],
  child: const ProductSearchPage(),
)
```

或者定义 feature provider，但只在该页面使用。

核心思路：

```text
状态范围越小越好；
真的跨页面共享，再提升到 app-level。
```

---

## 7. 常见 App-level Provider

```dart
authProvider
currentUserProvider
themeModeProvider
localeProvider
cartProvider
appConfigProvider
dioProvider
secureStorageProvider
sharedPreferencesProvider
routerProvider
```

这些通常在 app 任意位置都可能被依赖。

---

一句话理解：

```text
Web Global State 是跨页面共享状态；
Flutter/Riverpod 中通常用 ProviderScope 下的 app-level provider 表达。
但不要把所有状态都全局化：
跨页面共享才提升到 app-level，
页面局部状态保持局部。
```
