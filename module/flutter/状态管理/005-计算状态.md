# Derived State vs Computed Provider

Web 里的 Derived State 指“由已有状态计算出来的状态”，比如筛选后的列表、总价、是否可提交。

Flutter + Riverpod 中对应的是 computed Provider，也就是普通 `Provider` 依赖其他 provider 后计算出新值。

可以这样映射：

| Web Derived State  | Riverpod Computed Provider        |
| ------------------ | --------------------------------- |
| derived state      | computed provider                 |
| selector           | provider / `select`               |
| `useMemo` result   | `Provider`                        |
| computed atom      | derived Provider                  |
| Zustand selector   | `ref.watch(provider.select(...))` |
| Redux selector     | derived Provider / select         |
| Vue computed       | Provider                          |
| Jotai derived atom | Provider depending on provider    |

---

## 1. Web Derived State

React：

```tsx
const filteredProducts = useMemo(() => {
  return products.filter((item) => item.enabled);
}, [products]);
```

或者 Redux selector：

```ts
const totalPrice = useSelector(selectCartTotal);
```

这些状态不需要单独存储，因为它们可以从已有状态计算出来。

---

## 2. Riverpod computed Provider

Riverpod：

```dart
final productsProvider = Provider<List<Product>>((ref) {
  return [];
});

final enabledProductsProvider = Provider<List<Product>>((ref) {
  final products = ref.watch(productsProvider);
  return products.where((item) => item.enabled).toList();
});
```

使用：

```dart
final enabledProducts = ref.watch(enabledProductsProvider);
```

核心是：

```text
enabledProductsProvider 不自己持有源数据；
它依赖 productsProvider 并计算结果。
```

## 3. 总价示例

React：

```tsx
const total = cartItems.reduce(
  (sum, item) => sum + item.price * item.quantity,
  0
);
```

Riverpod：

```dart
final cartItemsProvider = Provider<List<CartItem>>((ref) {
  return [];
});

final cartTotalProvider = Provider<Decimal>((ref) {
  final items = ref.watch(cartItemsProvider);

  return items.fold(
    Decimal.zero,
    (sum, item) => sum + item.price * Decimal.fromInt(item.quantity),
  );
});
```

UI：

```dart
final total = ref.watch(cartTotalProvider);
```

---

## 4. 不要重复存储 Derived State

不推荐：

```dart
class CartState {
  const CartState({
    required this.items,
    required this.total,
  });

  final List<CartItem> items;
  final Decimal total;
}
```

如果 `total` 可以由 `items` 算出，更推荐：

```dart
final cartTotalProvider = Provider<Decimal>((ref) {
  final items = ref.watch(cartItemsProvider);
  return calculateTotal(items);
});
```

避免：

```text
items 和 total 不一致
更新逻辑重复
状态同步 bug
```

---

## 5. select：减少不必要 rebuild

如果只关心某个字段：

```dart
final count = ref.watch(
  cartProvider.select((state) => state.items.length),
);
```

这类似：

```text
Redux selector
Zustand selector
```

当 selector 结果不变时，可以减少 UI rebuild。

## 6. family computed provider

带参数的派生状态：

```dart
final productByIdProvider =
    Provider.family<Product?, String>((ref, productId) {
  final products = ref.watch(productsProvider);

  for (final product in products) {
    if (product.id == productId) {
      return product;
    }
  }

  return null;
});
```

使用：

```dart
final product = ref.watch(productByIdProvider(id));
```

类似：

```ts
selectProductById(state, id);
```

---

## 7. 怎么判断是否应该派生

适合作为 derived state：

```text
筛选结果
排序结果
总价
数量统计
是否为空
是否可提交
当前选中项详情
格式化后的展示文本
```

不适合派生、应该存储的状态：

```text
用户真实输入
服务端返回数据
分页游标
当前 tab
请求 loading/error
用户选择的筛选条件
```

---

一句话理解：

```text
Derived State 是由已有状态计算出来的值，不应该重复存储；
Riverpod 中用 Provider 依赖其他 provider 来表达 computed state，
必要时用 select 控制订阅粒度。
```
