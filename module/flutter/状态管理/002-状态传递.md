# React Context vs `InheritedWidget` / Provider

React Context 用来跨组件传递数据，避免 props 一层层传递。

Flutter 中底层对应的是 `InheritedWidget`，实际业务开发中更常用 Provider / Riverpod 这类封装。

可以这样映射：

| React Context           | Flutter                                       |
| ----------------------- | --------------------------------------------- |
| `createContext()`       | `InheritedWidget`                             |
| `Context.Provider`      | `InheritedWidget` 包住子树                    |
| `useContext()`          | `of(context)` / `context.watch` / `ref.watch` |
| Provider value          | inherited data / provider state               |
| props drilling 替代方案 | constructor drilling 替代方案                 |
| ThemeContext            | `Theme.of(context)`                           |
| AuthContext             | auth provider                                 |
| Global app state        | Provider / Riverpod                           |

---

## 1. React Context

React：

```tsx
const AuthContext = createContext<AuthState | null>(null);

function App() {
  return (
    <AuthContext.Provider value={authState}>
      <HomePage />
    </AuthContext.Provider>
  );
}
```

子组件读取：

```tsx
const auth = useContext(AuthContext);
```

核心是：

```text
在上层提供数据；
下层任意组件可以读取；
避免 props drilling。
```

---

## 2. Flutter InheritedWidget

Flutter 底层类似机制是 `InheritedWidget`：

```dart
class AuthScope extends InheritedWidget {
  const AuthScope({
    super.key,
    required this.authState,
    required super.child,
  });

  final AuthState authState;

  static AuthScope of(BuildContext context) {
    return context.dependOnInheritedWidgetOfExactType<AuthScope>()!;
  }

  @override
  bool updateShouldNotify(AuthScope oldWidget) {
    return authState != oldWidget.authState;
  }
}
```

使用：

```dart
AuthScope(
  authState: authState,
  child: const HomePage(),
)
```

子组件读取：

```dart
final auth = AuthScope.of(context).authState;
```

## 3. 实际项目更常用 Provider / Riverpod

手写 `InheritedWidget` 比较底层，业务中通常不会频繁直接写。

更常见的是：

```text
Provider
Riverpod
Bloc
GetIt + ValueNotifier
```

如果使用 Riverpod：

```dart
final authProvider = Provider<AuthState>((ref) {
  return AuthState();
});
```

读取：

```dart
final auth = ref.watch(authProvider);
```

可以理解为：

```text
React useContext(AuthContext)
≈ Riverpod ref.watch(authProvider)
```

---

## 4. Theme.of(context) 是典型例子

Flutter 里最常见的 inherited data 是 Theme：

```dart
final theme = Theme.of(context);
final colors = theme.colorScheme;
```

它的心智非常接近 React Context：

```text
MaterialApp 提供 Theme；
子树中的 Widget 通过 Theme.of(context) 读取。
```

类似 React：

```tsx
const theme = useContext(ThemeContext);
```

---

## 5. Context vs BuildContext

名字容易混淆。

React 的 Context 是：

```text
一种跨组件传递数据的机制。
```

Flutter 的 `BuildContext` 是：

```text
Widget 在 Element Tree 中的位置句柄。
```

Flutter 通过 `BuildContext` 向上查找：

```dart
Theme.of(context)
Navigator.of(context)
ScaffoldMessenger.of(context)
```

所以：

```text
React Context 是“数据容器”；
Flutter BuildContext 是“查找上下文数据的位置”。
```

## 6. Provider 的重建粒度

React Context 有一个常见问题：

```text
Provider value 改变后，消费该 Context 的组件可能重新渲染。
```

Flutter Provider/Riverpod 也要关注重建范围。

Riverpod 可以用：

```dart
ref.watch(provider)
```

监听状态变化。

只调用方法、不监听变化时用：

```dart
ref.read(provider.notifier)
```

Provider 包也有：

```dart
context.watch<T>()
context.read<T>()
context.select<T, R>()
```

用于控制是否 rebuild。

---

## 7. 什么时候用

| 场景             | Flutter 推荐                      |
| ---------------- | --------------------------------- |
| 主题、颜色、字体 | `ThemeData` / `Theme.of(context)` |
| 简单向下传数据   | `InheritedWidget` / Provider      |
| 业务状态共享     | Riverpod Provider / Notifier      |
| 异步数据状态     | FutureProvider / AsyncNotifier    |
| 只传一两层       | 构造参数直接传                    |
| 全局服务对象     | Provider / Repository provider    |

---

一句话理解：

```text
React Context 用 Provider/useContext 在组件树中共享数据；
Flutter 底层用 InheritedWidget 做类似事情，
业务开发中通常通过 Provider/Riverpod 使用它。
React Context 是数据机制，
Flutter BuildContext 是在 Widget Tree 中查找这些数据的位置。
```
