# Components / Pages / Services vs Widgets / Pages / Repositories

Web 项目里常见分层是：

```text
components
pages
services
```

Flutter 里对应常见是：

```text
widgets
pages
repositories
```

但 Flutter 通常还会多出状态层和模型层，比如：

```text
providers / notifiers
models / DTOs
data sources
```

可以这样映射：

| Web                | Flutter                          |
| ------------------ | -------------------------------- |
| Component          | Widget                           |
| Page Component     | Page / Screen Widget             |
| Service            | Repository / API Service         |
| API Service        | Remote Data Source / API Service |
| Store / Hook       | Provider / Notifier              |
| Types / DTO        | Model / DTO                      |
| Shared Components  | Core Widgets                     |
| Feature Components | Feature Widgets                  |
| Utils              | Utils / Extensions               |

---

## 1. Web 常见结构

```text
src/
  pages/
    ProductListPage.tsx
  components/
    ProductCard.tsx
    EmptyState.tsx
  services/
    productApi.ts
  stores/
    productStore.ts
  types/
    product.ts
```

职责通常是：

```text
pages：路由页面
components：可复用 UI
services：接口请求和业务服务
stores/hooks：状态逻辑
types：类型定义
```

---

## 2. Flutter 常见结构

```text
lib/
  features/
    product/
      presentation/
        pages/
          product_list_page.dart
        widgets/
          product_card.dart
      application/
        product_list_provider.dart
      domain/
        models/
          product.dart
        repositories/
          product_repository.dart
      data/
        repositories/
          remote_product_repository.dart
        datasources/
          product_api_service.dart
        models/
          product_dto.dart
```

职责通常是：

```text
pages：路由直接打开的页面
widgets：页面内部或跨页面复用 UI
repositories：业务数据入口
api service/data source：HTTP、本地库等数据源
providers/notifiers：状态和用例编排
models/dto：数据结构
```

---

## 3. Component vs Widget

Web：

```tsx
<ProductCard product={product} />
```

Flutter：

```dart
ProductCard(product: product)
```

区别：

```text
Web Component 最终渲染 DOM；
Flutter Widget 最终进入 Flutter 渲染管线。
```

项目组织上：

| 类型        | Flutter 位置                          |
| ----------- | ------------------------------------- |
| 通用 UI     | `lib/core/widgets`                    |
| 业务 UI     | `lib/features/*/presentation/widgets` |
| 页面私有 UI | page 文件内 `_PrivateWidget`          |

---

## 4. Page vs Page Widget

Web：

```tsx
<Route path="/products" element={<ProductListPage />} />
```

Flutter：

```dart
GoRoute(
  path: '/products',
  builder: (context, state) => const ProductListPage(),
)
```

Page 在两边都负责：

```text
读取路由参数
组织页面布局
连接状态层
组合子组件
处理页面级交互
```

---

## 5. Service vs Repository

Web 中 `service` 这个词经常很宽：

```text
productApi
authService
storageService
trackingService
```

Flutter 更建议拆清楚：

| 职责           | 名称                             |
| -------------- | -------------------------------- |
| 发 HTTP 请求   | API Service / Remote Data Source |
| 读写本地数据库 | Local Data Source                |
| 聚合数据来源   | Repository                       |
| 业务动作编排   | Notifier / Use Case              |
| 第三方 SDK     | Service                          |

Repository 不只是“请求接口”，还可以负责：

```text
DTO 转 Domain Model
缓存
错误转换
远程 + 本地数据合并
离线策略
```

---

## 6. 推荐依赖方向

```text
Page/Widget
→ Provider/Notifier
→ Repository
→ API Service / Local Data Source
```

UI 不直接调用 Dio：

```text
Widget 不知道 URL
Widget 不解析 JSON
Widget 不管理缓存策略
```

这样更容易测试和维护。

---

## 7. 简化版映射

如果不想一开始分太细，可以先用：

```text
features/product/
  product_page.dart
  product_card.dart
  product_provider.dart
  product_repository.dart
  product_model.dart
```

等业务复杂后再拆成：

```text
presentation
application
domain
data
```

一句话理解：

```text
Web 的 components/pages/services 在 Flutter 中大致对应 widgets/pages/repositories。
但 Flutter 更推荐把 HTTP 细节放到 API Service/Data Source，
把业务数据入口放到 Repository，
再由 Provider/Notifier 把状态暴露给 Page/Widget。
```
