# REST API Client vs Repository / API Service

Web 里常把 REST 请求封装成 API Client 或 Service，例如：

```ts
productApi.fetchProducts();
orderApi.createOrder();
```

Flutter 中也会封装，但更常见分层是：

```text
Dio/API Service：负责 HTTP 请求
Repository：负责业务数据获取与转换
Provider/Notifier：负责状态管理
Widget：负责渲染
```

可以这样映射：

| Web REST API Client  | Flutter                          |
| -------------------- | -------------------------------- |
| axios instance       | Dio instance                     |
| API client           | API Service / Remote Data Source |
| service function     | repository method                |
| DTO type             | model / DTO class                |
| response mapper      | `fromJson` / mapper              |
| React Query query fn | Repository method                |
| service layer        | data layer                       |
| domain API           | Repository interface             |
| mock client          | fake repository                  |

---

## 1. Web API Client

Web：

```ts
export async function fetchProducts() {
  const response = await api.get('/products');
  return response.data;
}
```

或者：

```ts
export const productApi = {
  fetchProducts: () => api.get('/products'),
  fetchProduct: (id: string) => api.get(`/products/${id}`),
};
```

组件或 hook 调用：

```ts
const products = await productApi.fetchProducts();
```

---

## 2. Flutter API Service

Flutter 中可以先封装 HTTP 细节：

```dart
class ProductApiService {
  const ProductApiService(this.dio);

  final Dio dio;

  Future<List<dynamic>> fetchProducts() async {
    final response = await dio.get('/products');
    return response.data as List<dynamic>;
  }

  Future<Map<String, dynamic>> fetchProduct(String id) async {
    final response = await dio.get('/products/$id');
    return response.data as Map<String, dynamic>;
  }
}
```

这个层主要负责：

```text
URL
HTTP method
query/body
headers
response 原始结构
```

---

## 3. Repository

Repository 更偏业务数据入口：

```dart
class ProductRepository {
  const ProductRepository(this.apiService);

  final ProductApiService apiService;

  Future<List<Product>> fetchProducts() async {
    final data = await apiService.fetchProducts();

    return data
        .map((item) => Product.fromJson(item as Map<String, dynamic>))
        .toList();
  }

  Future<Product> fetchProduct(String id) async {
    final data = await apiService.fetchProduct(id);
    return Product.fromJson(data);
  }
}
```

Repository 负责：

```text
调用 API Service
JSON 转 Model
合并远程/本地数据
缓存策略
错误转换
屏蔽数据来源差异
```

---

## 4. 为什么不直接在 Widget 里调 dio

不推荐：

```dart
ElevatedButton(
  onPressed: () async {
    final response = await Dio().get('/products');
  },
)
```

原因：

```text
UI 和网络细节耦合
难测试
难复用
错误处理分散
拦截器/缓存/解析逻辑混乱
```

更推荐：

```text
Widget → Provider/Notifier → Repository → API Service → Dio
```

---

## 5. Repository Interface

如果项目更强调可测试性，可以定义抽象：

```dart
abstract class ProductRepository {
  Future<List<Product>> fetchProducts();
}
```

实现：

```dart
class RemoteProductRepository implements ProductRepository {
  const RemoteProductRepository(this.apiService);

  final ProductApiService apiService;

  @override
  Future<List<Product>> fetchProducts() async {
    // ...
  }
}
```

测试时替换：

```dart
class FakeProductRepository implements ProductRepository {
  @override
  Future<List<Product>> fetchProducts() async {
    return [fakeProduct];
  }
}
```

## 6. Riverpod 注入

```dart
final dioProvider = Provider<Dio>((ref) {
  return Dio(BaseOptions(baseUrl: 'https://api.example.com'));
});

final productApiServiceProvider = Provider<ProductApiService>((ref) {
  return ProductApiService(ref.watch(dioProvider));
});

final productRepositoryProvider = Provider<ProductRepository>((ref) {
  return RemoteProductRepository(
    ref.watch(productApiServiceProvider),
  );
});
```

页面状态：

```dart
final productsProvider = FutureProvider<List<Product>>((ref) {
  return ref.watch(productRepositoryProvider).fetchProducts();
});
```

## 7. 分层怎么选

| 项目规模     | 推荐                                            |
| ------------ | ----------------------------------------------- |
| 很小 demo    | Repository 直接调 Dio                           |
| 普通业务 App | API Service + Repository                        |
| 大型业务 App | DataSource + Repository Interface + Mapper      |
| 需要离线缓存 | RemoteDataSource + LocalDataSource + Repository |
| 需要大量测试 | 抽象 Repository + Fake 实现                     |

---

## 8. 对应关系总结

```text
Dio
≈ axios instance

API Service
≈ productApi/orderApi 这种 HTTP 封装

Repository
≈ 更业务化的数据访问层，负责把接口数据变成 App 可用模型

Provider/Notifier
≈ React Query hook / Zustand action / Redux thunk 的状态入口
```

一句话理解：

```text
Web REST API Client 通常封装 axios/fetch 请求；
Flutter 中更推荐把 HTTP 细节放在 API Service，
把业务数据获取、转换、缓存和错误抽象放在 Repository，
再由 Provider/Notifier 提供给 Widget 使用。
```
