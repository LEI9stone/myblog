# Token Header vs Auth Interceptor

Web 里常在请求头里手动带 token：

```ts
headers: {
  Authorization: `Bearer ${token}`;
}
```

Flutter/Dart 里如果使用 `dio`，通常会把 token 注入逻辑放到 Auth Interceptor 中，避免每个请求重复写 header。

可以这样映射：

| Web                    | Flutter / Dio                      |
| ---------------------- | ---------------------------------- |
| request header         | request headers                    |
| `Authorization` header | `options.headers['Authorization']` |
| axios interceptor      | dio interceptor                    |
| token storage          | secure storage                     |
| refresh token          | auth interceptor / auth repository |
| 401 handling           | `onError` 中处理                   |
| retry request          | interceptor 中重新发起请求         |
| logout on expired      | 清理 token + 跳登录                |

---

## 1. Web 手动加 Token Header

Web：

```ts
await axios.get('/profile', {
  headers: {
    Authorization: `Bearer ${token}`,
  },
});
```

如果每个接口都这样写，会有问题：

```text
重复代码多
容易漏传 token
token 更新后不好统一处理
401 处理分散
```

---

## 2. axios interceptor

Web 中更常见：

```ts
api.interceptors.request.use((config) => {
  const token = getToken();

  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }

  return config;
});
```

Flutter 中对应：

```dart
dio.interceptors.add(
  InterceptorsWrapper(
    onRequest: (options, handler) async {
      final token = await tokenStorage.readAccessToken();

      if (token != null && token.isNotEmpty) {
        options.headers['Authorization'] = 'Bearer $token';
      }

      handler.next(options);
    },
  ),
);
```

---

## 3. Auth Interceptor 的职责

Auth Interceptor 通常负责：

```text
请求前读取 token
自动添加 Authorization header
遇到 401 时尝试刷新 token
刷新失败后清理登录态
必要时重试原请求
```

它不应该负责：

```text
具体业务接口解析
页面跳转细节
复杂 UI 提示
业务数据转换
```

这些应该放在 Repository、Auth State 或 UI 层处理。

---

## 4. Token 存储

Web 常见：

```text
localStorage
sessionStorage
cookie
memory
```

Flutter 常见：

```text
flutter_secure_storage
shared_preferences
memory cache
```

认证 token 更推荐：

```text
flutter_secure_storage
```

例如：

```dart
abstract class TokenStorage {
  Future<String?> readAccessToken();
  Future<void> writeAccessToken(String token);
  Future<void> clear();
}
```

---

## 5. 401 处理

Dio：

```dart
dio.interceptors.add(
  InterceptorsWrapper(
    onError: (error, handler) async {
      if (error.response?.statusCode == 401) {
        // refresh token or logout
      }

      handler.next(error);
    },
  ),
);
```

常见流程：

```text
请求返回 401
尝试用 refresh token 换 access token
刷新成功：重试原请求
刷新失败：清理 token，进入未登录状态
```

---

## 6. 避免循环刷新

实现 refresh token 时要注意：

```text
刷新 token 的请求本身不要再次触发同一个 auth interceptor 死循环
多个请求同时 401 时不要并发刷新多次
刷新失败后不要无限 retry
```

常见做法：

```text
刷新接口使用单独 Dio 实例
或在 options.extra 标记 skipAuth
用锁/队列合并并发刷新
```

---

## 7. Repository 里的使用方式

有了 Auth Interceptor 后，业务 Repository 不需要关心 token header：

```dart
class UserRepository {
  const UserRepository(this.dio);

  final Dio dio;

  Future<User> fetchProfile() async {
    final response = await dio.get('/profile');
    return User.fromJson(response.data as Map<String, dynamic>);
  }
}
```

Repository 只表达业务请求：

```text
GET /profile
POST /orders
GET /products
```

认证细节由拦截器统一处理。

---

一句话理解：

```text
Token Header 是每个 HTTP 请求里的认证信息；
Auth Interceptor 是统一添加和维护认证信息的请求中间层。
Web axios 和 Flutter dio 都推荐用 interceptor 自动注入 token，
并集中处理 401、刷新 token 和登出逻辑。
```
