# Retry / Timeout vs Dio Options

Web 里请求超时和重试通常通过 axios 配置、AbortController、拦截器或 React Query 配置实现。

Flutter/Dart 使用 `dio` 时，对应主要是：

```dart
BaseOptions
Options
Interceptors
Retry interceptor
```

可以这样映射：

| Web                 | Flutter / Dio                                       |
| ------------------- | --------------------------------------------------- |
| axios timeout       | `connectTimeout` / `receiveTimeout` / `sendTimeout` |
| fetch timeout       | `AbortController` + timer / Dio timeout             |
| retry option        | interceptor / 手写 retry                            |
| React Query retry   | Provider/Notifier 层 retry                          |
| exponential backoff | retry delay strategy                                |
| request config      | `Options`                                           |
| global axios config | `BaseOptions`                                       |
| per-request config  | request-level `Options`                             |

---

## 1. Timeout

axios：

```ts
const api = axios.create({
  timeout: 10000,
});
```

dio：

```dart
final dio = Dio(
  BaseOptions(
    baseUrl: 'https://api.example.com',
    connectTimeout: const Duration(seconds: 10),
    receiveTimeout: const Duration(seconds: 10),
    sendTimeout: const Duration(seconds: 10),
  ),
);
```

Dio 常见 timeout：

| Dio Timeout      | 含义                 |
| ---------------- | -------------------- |
| `connectTimeout` | 建立连接超时时间     |
| `sendTimeout`    | 发送请求数据超时时间 |
| `receiveTimeout` | 接收响应数据超时时间 |

---

## 2. 单个请求覆盖 Timeout

```dart
await dio.get(
  '/products',
  options: Options(
    receiveTimeout: const Duration(seconds: 5),
  ),
);
```

适合：

```text
某个接口特别慢
上传下载需要更长超时
搜索接口需要更短超时
```

---

## 3. Timeout 错误处理

```dart
try {
  await dio.get('/products');
} on DioException catch (error) {
  switch (error.type) {
    case DioExceptionType.connectionTimeout:
    case DioExceptionType.sendTimeout:
    case DioExceptionType.receiveTimeout:
      // handle timeout
      break;
    default:
      rethrow;
  }
}
```

常见 UI：

```text
网络超时
请检查网络后重试
```

---

## 4. Retry

Dio 本身不等于 React Query，不会自动为所有请求做复杂 retry 策略。

常见实现方式有三种：

```text
Repository/Notifier 手写 retry
Dio interceptor 统一 retry
使用第三方 retry interceptor
```

简单手写：

```dart
Future<T> retry<T>(
  Future<T> Function() task, {
  int maxAttempts = 3,
}) async {
  Object? lastError;

  for (var attempt = 1; attempt <= maxAttempts; attempt++) {
    try {
      return await task();
    } catch (error) {
      lastError = error;

      if (attempt == maxAttempts) {
        rethrow;
      }

      await Future.delayed(
        Duration(milliseconds: 300 * attempt),
      );
    }
  }

  throw lastError!;
}
```

使用：

```dart
final response = await retry(() {
  return dio.get('/products');
});
```

---

## 5. 哪些请求适合 Retry

适合自动重试：

```text
GET 请求
临时网络抖动
超时
502 / 503 / 504
幂等接口
```

不适合随便自动重试：

```text
创建订单
支付
提交表单
扣库存
发送验证码
非幂等 POST
```

这点很重要：重试可能导致重复提交。

---

## 6. Retry 放哪一层

| 场景                      | 推荐位置                           |
| ------------------------- | ---------------------------------- |
| 所有 GET 临时错误统一重试 | Dio interceptor                    |
| 某个接口特殊重试          | Repository                         |
| 用户点击“重试”            | UI / Notifier                      |
| 页面数据重新加载          | `ref.invalidate` / Notifier reload |
| 提交类操作失败重试        | 用户明确触发                       |

---

## 7. UI Retry

Web：

```tsx
<ErrorView onRetry={refetch} />
```

Flutter：

```dart
ErrorView(
  onRetry: () {
    ref.invalidate(productsProvider);
  },
)
```

或者：

```dart
ErrorView(
  onRetry: () {
    ref.read(productListProvider.notifier).reload();
  },
)
```

---

一句话理解：

```text
Web 里 timeout/retry 常由 axios、fetch 封装或 React Query 管；
Flutter dio 用 BaseOptions/Options 配 timeout，
retry 通常放在 interceptor、Repository 或 Notifier 层。
超时可以统一处理，但自动重试只适合幂等请求，提交类操作要谨慎。
```
