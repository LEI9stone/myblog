# Loading / Error / Success State vs `AsyncValue`

Web 里异步请求常手动维护三种状态：

```text
loading
error
data
```

Flutter + Riverpod 中对应的是：

```dart
AsyncValue<T>
```

它把异步状态统一表达为：

```text
AsyncLoading
AsyncError
AsyncData
```

可以这样映射：

| Web Async State         | Riverpod AsyncValue               |
| ----------------------- | --------------------------------- |
| `isLoading: true`       | `AsyncLoading`                    |
| `error`                 | `AsyncError`                      |
| `data`                  | `AsyncData<T>`                    |
| `refetch`               | `ref.invalidate` / `ref.refresh`  |
| `try/catch` 包状态      | `AsyncValue.guard`                |
| conditional render      | `switch` / `when`                 |
| stale data + refreshing | `AsyncValue` refresh/reload flags |
| query result            | `AsyncValue<T>`                   |

---

## 1. Web 手动状态

React：

```tsx
const [loading, setLoading] = useState(false);
const [error, setError] = useState<Error | null>(null);
const [data, setData] = useState<Product[]>([]);
```

请求：

```tsx
try {
  setLoading(true);
  const result = await fetchProducts();
  setData(result);
} catch (error) {
  setError(error);
} finally {
  setLoading(false);
}
```

问题是：

```text
状态字段容易不一致；
loading/error/data 组合复杂；
每个请求都重复写。
```

---

## 2. AsyncValue

Riverpod：

```dart
final productsProvider = FutureProvider<List<Product>>((ref) async {
  final repository = ref.watch(productRepositoryProvider);
  return repository.fetchProducts();
});
```

UI 中：

```dart
final products = ref.watch(productsProvider);
```

`products` 是：

```dart
AsyncValue<List<Product>>
```

它可能是：

```dart
AsyncLoading()
AsyncError(error, stackTrace)
AsyncData(value)
```

---

## 3. 渲染状态

```dart
switch (products) {
  case AsyncLoading():
    return const LoadingView();

  case AsyncError(:final error):
    return ErrorView(error: error);

  case AsyncData(:final value):
    return ProductList(products: value);
}
```

或者：

```dart
products.when(
  loading: () => const LoadingView(),
  error: (error, stackTrace) => ErrorView(error: error),
  data: (value) => ProductList(products: value),
);
```

对应 Web：

```tsx
if (loading) return <Loading />;
if (error) return <ErrorView />;
return <ProductList products={data} />;
```

---

## 4. AsyncValue.guard

手动请求时可以用：

```dart
state = await AsyncValue.guard(() async {
  return repository.fetchProducts();
});
```

它会自动把结果转成：

```text
成功 → AsyncData
失败 → AsyncError
```

常用于 `AsyncNotifier`：

```dart
Future<void> reload() async {
  state = const AsyncLoading();

  state = await AsyncValue.guard(() async {
    final repository = ref.read(productRepositoryProvider);
    return repository.fetchProducts();
  });
}
```

---

## 5. Refresh / Reload

Web 中：

```text
isFetching
isLoading
isRefetching
```

Riverpod 的 `AsyncValue` 也能表达刷新中的细节，比如保留旧数据同时刷新。

常见 UI 策略：

```text
首次加载：显示全屏 loading
已有数据刷新：保留旧数据 + 下拉刷新/顶部 loading
失败：显示错误态或保留旧数据提示错误
```

---

## 6. Empty State 不等于 AsyncData

加载成功但数据为空：

```dart
case AsyncData(:final value) when value.isEmpty:
  return const EmptyState();
```

这不是 Error，也不是 Loading，而是：

```text
成功拿到空数据。
```

所以常见四态是：

```text
loading
error
empty
data
```

`AsyncValue` 负责前三个异步基础状态，`empty` 由 data 内容判断。

---

## 7. 什么时候不用 AsyncValue

简单局部按钮提交：

```text
isSubmitting
```

可以用 bool。

但如果是服务端数据请求，尤其有：

```text
loading
error
data
refresh
retry
```

就适合用 `AsyncValue`。

---

一句话理解：

```text
Web 常手动维护 loading/error/data；
Riverpod 用 AsyncValue<T> 统一表达异步状态：
AsyncLoading、AsyncError、AsyncData。
UI 根据 AsyncValue 渲染 loading、error、empty 和 success。
```
