# Performance Tab vs Flutter Performance View

Web 里的 Performance Tab 用来分析页面加载、JavaScript 执行、样式计算、布局、绘制、长任务和 FPS。

Flutter DevTools 的 Performance View 用来分析 Flutter 帧渲染、UI thread、Raster thread、jank、rebuild、layout、paint 和 shader 等性能问题。

可以这样映射：

| Web Performance Tab | Flutter Performance View         |
| ------------------- | -------------------------------- |
| FPS                 | frame chart                      |
| long task           | long frame / jank                |
| JS main thread      | UI thread                        |
| compositor/raster   | Raster thread                    |
| style recalculation | 无 CSS，对应 layout/rebuild 相关 |
| layout              | Flutter layout phase             |
| paint               | Flutter paint/raster             |
| timeline            | timeline events                  |
| flame chart         | CPU profiler / timeline          |
| forced reflow       | layout thrash / repeated layout  |
| memory pressure     | Memory view                      |

---

## 1. Web Performance Tab

Web 里重点看：

```text
JS 执行是否阻塞主线程
layout/reflow 是否频繁
paint/composite 是否过重
long task 是否超过 50ms
资源加载是否拖慢首屏
FPS 是否掉帧
```

常见问题：

```text
大 JS bundle
频繁 DOM 操作
强制同步布局
复杂 CSS/filter
大图加载
主线程长任务
```

---

## 2. Flutter Performance View

Flutter 里重点看：

```text
UI thread 时间
Raster thread 时间
Frame 是否超过预算
Jank
Rebuild 是否过多
Layout/Paint 是否过重
Shader 编译是否卡顿
图片解码是否慢
```

Flutter 一帧通常要在预算内完成：

```text
60fps: 16.6ms
120fps: 8.3ms
```

超过预算就可能掉帧。

---

## 3. UI Thread vs Raster Thread

Flutter 渲染通常关注两条线程：

| Flutter       | 负责                                     |
| ------------- | ---------------------------------------- |
| UI thread     | Dart 代码、build、layout、paint 指令生成 |
| Raster thread | 栅格化、把绘制指令变成像素               |

如果 UI thread 慢，可能是：

```text
build 太重
同步计算太多
JSON 解析阻塞
列表一次构建太多
状态更新范围过大
```

如果 Raster thread 慢，可能是：

```text
复杂阴影
大图片
过多透明/裁剪
复杂 CustomPaint
shader 编译
```

---

## 4. Jank

Web 中掉帧常看 long task 和 FPS。

Flutter 中常看 jank：

```text
某帧耗时超过预算，导致动画/滚动不流畅。
```

Performance View 会显示帧图，可以定位哪一帧慢、慢在 UI 还是 Raster。

---

## 5. 常见 Flutter 性能问题

```text
ListView 没用 builder
大列表一次性渲染
build 中做重计算
build 中发请求
图片尺寸过大
频繁 setState 到大范围
复杂阴影/clip
不必要的 opacity layer
CustomPaint 太重
动画中触发大量 layout
```

---

## 6. Web 优化 vs Flutter 优化

| Web 优化           | Flutter 对应                                  |
| ------------------ | --------------------------------------------- |
| 减少 DOM 操作      | 减少不必要 rebuild                            |
| 虚拟列表           | `ListView.builder` / Sliver                   |
| 避免 forced reflow | 避免反复 layout / intrinsic 过度使用          |
| 图片压缩           | 使用合适尺寸图片 / cache                      |
| code splitting     | 延迟加载模块 / 减少启动工作                   |
| off main thread    | isolate / compute                             |
| CSS transform 动画 | Flutter transform/opacity 动画，避免重 layout |

---

## 7. 工具组合

Flutter 性能排查常用：

```text
Performance View
Widget rebuild profiler
CPU Profiler
Memory View
Network View
Flutter Inspector
debug flags
```

常见 debug flag：

```dart
debugPaintSizeEnabled
debugRepaintRainbowEnabled
debugProfileBuildsEnabled
```

这些主要在调试时使用。

---

一句话理解：

```text
Web Performance Tab 分析浏览器主线程、layout、paint、资源和 FPS；
Flutter Performance View 分析 Flutter 每帧的 UI thread、Raster thread 和 jank。
Web 优化关注 DOM/CSS/JS；
Flutter 优化关注 rebuild、layout、paint、raster、图片和异步计算。
```
