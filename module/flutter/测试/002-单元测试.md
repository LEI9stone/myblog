# Unit Test vs Dart Test

Web 里的 Unit Test 通常用 Jest/Vitest 测纯函数、业务逻辑、状态 reducer、工具函数。

Dart/Flutter 中对应的是 Dart Test，也就是用 `test()` 测普通 Dart 逻辑。

可以这样映射：

| Web Unit Test      | Dart Test                      |
| ------------------ | ------------------------------ |
| `describe`         | `group`                        |
| `it` / `test`      | `test`                         |
| `expect(...).toBe` | `expect(..., equals(...))`     |
| `beforeEach`       | `setUp`                        |
| `afterEach`        | `tearDown`                     |
| mock function      | mocktail / Mockito             |
| fake timer         | fake_async                     |
| pure function test | Dart function test             |
| service test       | Repository/Service test        |
| reducer test       | Notifier/state transition test |

---

## 1. Web Unit Test

Vitest/Jest：

```ts
describe('formatPrice', () => {
  it('formats price', () => {
    expect(formatPrice(99)).toBe('¥99.00');
  });
});
```

---

## 2. Dart Test

Dart：

```dart
import 'package:flutter_test/flutter_test.dart';

void main() {
  group('formatPrice', () {
    test('formats price', () {
      expect(formatPrice(99), equals('¥99.00'));
    });
  });
}
```

`flutter_test` 已经包含常用 test API。纯 Dart package 也可以用：

```dart
package:test/test.dart
```

Flutter App 中通常直接用：

```dart
package:flutter_test/flutter_test.dart
```

---

## 3. 适合 Unit Test 的内容

适合：

```text
格式化函数
金额计算
JSON mapper
DTO -> Domain mapper
表单校验
状态转换
Repository 逻辑
Provider/Notifier 逻辑
排序/筛选函数
```

不需要 Widget 环境的逻辑，都优先用 `test()`。

---

## 4. setUp / tearDown

Web：

```ts
beforeEach(() => {
  repo = createFakeRepo();
});
```

Dart：

```dart
late FakeProductRepository repository;

setUp(() {
  repository = FakeProductRepository();
});

tearDown(() {
  repository.dispose();
});
```

---

## 5. 异步测试

Web：

```ts
it('loads products', async () => {
  const products = await repo.fetchProducts();
  expect(products).toHaveLength(1);
});
```

Dart：

```dart
test('loads products', () async {
  final products = await repository.fetchProducts();

  expect(products, hasLength(1));
});
```

---

## 6. 异常测试

Web：

```ts
await expect(repo.fetchProducts()).rejects.toThrow();
```

Dart：

```dart
expect(
  () => repository.fetchProducts(),
  throwsA(isA<ApiException>()),
);
```

如果是 Future：

```dart
await expectLater(
  repository.fetchProducts(),
  throwsA(isA<ApiException>()),
);
```

---

## 7. Notifier / State 测试

如果用 Riverpod，可以测试状态逻辑：

```dart
final container = ProviderContainer(
  overrides: [
    productRepositoryProvider.overrideWithValue(fakeRepository),
  ],
);

addTearDown(container.dispose);

final result = await container.read(productsProvider.future);

expect(result, hasLength(1));
```

这类似测试 Redux reducer / Zustand store / React Query hook 的核心逻辑，但不需要渲染 UI。

---

## 8. Unit Test vs Widget Test

| 测试类型         | 用途                   |
| ---------------- | ---------------------- |
| Dart `test()`    | 纯逻辑、状态、数据转换 |
| `testWidgets()`  | Widget 渲染和交互      |
| Golden test      | 视觉回归               |
| Integration test | 真机/模拟器端到端流程  |

优先级：

```text
能用 unit test 覆盖的逻辑，就不要强行上 widget test。
```

因为 unit test 更快、更稳定、更容易定位问题。

---

一句话理解：

```text
Web Unit Test 对应 Dart 的 test()；
它适合测试纯 Dart 逻辑、数据转换、状态迁移和服务层行为。
Flutter UI 渲染才需要 testWidgets。
```
